## 0. 使命句（提议直接入宪法序言 + 首页 hero）

> **理解 AI，不应该依赖信任，而应该依赖观察。**
> **Don't trust AI. Observe AI.**

实现方式副句（hero 下一行 / 关于页）：我们不是把 AI 的数据画出来，我们把 AI 的思考翻译成人类能够理解的语言。

这句使命直接对应 Evidence First：它把显微镜、真实 Trace、Every Pixel Has Evidence、Dynamicland 的无隐藏状态串成一条线——让人们**通过观察而不是相信**理解 AI。

产品最终定位不是 AI Chat UI，也不只是 AI Visualization，而是 **AI Understanding Interface / AI Literacy Interface**：
让第一次接触 AI 的人在 ~20 分钟内建立正确心智模型——为什么不是数据库、不是搜索、不是提前写好的；
为什么温度有影响；为什么 Agent 会失败；为什么 RAG 会幻觉。
北极星指标（远期）：用 Behavior Bench 思路做「使用前后心智模型问卷」前后测。

## 1. P27 · Cognitive First（认知优先 / Evidence before Explanation）

**条文（v2，按创始人改句）**：
**界面优先呈现可观察的证据，再帮助用户形成理解。**
呈现链固定为：Evidence → Pattern → Meaning → Explanation（可选）；禁止倒序（先下结论再补证据）。
边界说明：P27 反对的是**抢在证据前面下结论**，不是反对解释。Temperature、top-p、seed、softmax、Agent handoff 这类用户不可能自行发现的机制，仍然需要解释——但解释永远出现在证据之后、且默认下潜。

**四问升五问**（P26 检验追加第五问，写入合规速查表）：

1. 这是什么？
2. 为什么会出现？
3. 它说明 AI 正在发生什么？
4. 用户看完这一眼获得了什么新的理解？
5. **能不能不写一句解释，用户自己也能看懂？**

答不全 = 装饰，删除；第五问答「不能」= 先重做呈现方式，再考虑加解释。

**与 P25/P26 的关系（逻辑链）**：
P25 每个像素都有证据 → P26 证据必须翻译成意义 → P27 证据先于解释上场，理解由用户在观察中形成。

**立即适用的倒转清单**（现状「先解释后展示」→ 目标「先展示后解释」）：

| 现状（告诉） | 目标（让用户看见） |
|---|---|
| 决策日志一句「它几乎是掷硬币」 | 先呈现两根几乎等高的概率条（本身 20.1% ↔ 这个词 20.1%），胜者落下；「掷硬币」降为下潜标注 |
| 「温度 0.7 让它没选第一名」 | 先呈现 rank1 长条 vs 被选中的短条 + 抽签动线；文字降为下潜 |
| 「这一步它的候选最分散」 | 先呈现 8 根均匀矮条 vs 邻步一根独大的对比 |
| 思考字幕直接宣读结论 | 字幕降为「画面已经说了什么」的复述层，可关 |

## 2. P28 · One Screen, One Question（一屏只回答一个问题）

**条文（提议）**：任何一屏在任何时刻只回答一个问题；其余所有信息都是这个答案的支撑，默认下潜。
设计评审新增固定一问：**「这一屏，到底回答哪个问题？」** 答不出或答案多于一个 = 重新分层。

各页面的「本屏问题」标注（拍板即为验收口径）：

| 屏 | 本屏唯一问题 |
|---|---|
| 生成中（实况） | AI 现在为什么写这个？ |
| 完成态复盘 / Replay | AI 哪里最犹豫？ |
| RAG 舞台 | AI 为什么引用这里？ |
| Agent 规划 | AI 为什么决定这么计划/调用？ |
| 采样显微镜（下潜） | 换个温度它会写什么？ |
| 概率地形（下潜） | 整条路径的地形长什么样？ |
| 对比 | 两次运行从哪里分岔？ |

反面案例 A（创始人截图）：生成中一屏同时回答 Sampling/Entropy/Token/Replay/Inspector/3D 七个问题 = 违宪。

## 4. Questions 组织 UI（信息架构级改动，本稿最重的一条）

左栏从「事件列表」变成「问题列表」。v2 关键升级（创始人第二条）：**问题必须来自用户阅读正文时自然产生的疑问，而不是 AI Debug 问题**。

两层问题：

**读者层（默认，锚定正文）**——问题挂在正文具体的词上，随阅读产生：

| 问题（界面原文，锚定正文） | 证据来源 | 展开后呈现（P27 顺序：先画面后复述） |
|---|---|---|
| 为什么它写「形成」？ | 该步 topk + gap | 「形成 25.7%」↔「看起来 25.6%」两根近等高条摇摆，胜者落下 |
| 为什么它没写「我」？ | 选中 rank>1 + 温度/seed | rank1 长条 vs 被抽中的短条 + 抽签动线；采样管线下潜 |
| 为什么它突然去搜索？ | RetrievalRecord + 触发时机 | 检索前后的上下文对照 + 命中（绿）/弃用（虚线暗）文档 |
| 为什么这里写得特别慢？ | dt >3× 均值 | 该步耗时凸起 vs 全程节奏轨 |
| 为什么它先写了一份计划？ | agent plan 子运行事件 | 计划原文逐字流 + 耗时 + 接力交棒 |

**专业层（下潜，Debug 口径保留不删）**：它什么时候开始犹豫？哪一步熵最高？再跑一次会一样吗？——现有决策时刻/事件徽章归入此层。

**诚实缺席清单**（按 P9 不出现在问题列表，或出现但明确标注「暂无法回答」）：
它为什么会想到 X？（需 hidden state/circuit）· 它在注意哪些词？（需 attention 导出）· 它理解了吗？（主观状态，永不声称）。

交互：读者层问题锚定正文词旁（阅读到即看到）；点开 = 证据画面（先看见）+ 一句复述（后解释）+ 跳步。

## 5. Narrative Grammar（叙事语法，全站组件统一语言）

所有视觉组件必须归入四种语法之一，评审时标注归属；归不进 = 重新设计：

| 语法 | 定义 | 现有组件归位示例 |
|---|---|---|
| **Observation** 观察 | 用户只是看一个事实 | 当前 token、速度、把握度着色正文 |
| **Comparison** 对比 | 永远两个东西并置 | Winner vs Loser 概率条、这一步 vs 上一步、两次运行对比 |
| **Transition** 变化 | 一定发生状态转变 | 候选 → 胜者落下（BirthScene）、检索 → 送入上下文、规划 → 作答 |
| **Consequence** 结果 | 告诉用户因此发生了什么 | 「因此写出了『形成』」、分岔点之后的两条正文 |

组合规则：一个完整叙事单元 = Observation → Comparison → Transition → Consequence（可省略但不可乱序）；这与 P27 的 Evidence→Pattern→Meaning→Explanation 链一一对应。写入 `AODL/02-Visual-DNA.md` 作为组件级语法。

## 6. 运行中一屏的叙事主线重构（反面案例 A，P28 的第一个落地）

**现状问题**（创始人截图，生成中页面）：Debug 条、五段流水线、此刻卡、Sampling Inspector、采样显微镜、3D 柱林六层专业信息同场，无主次、无落点，普通人看不懂。

**目标：一屏一主线**。运行中默认只保留：

1. **主叙事区**：正在写出的文字（把握度着色）+ 当前时刻的犹豫可视（两根条/多根条，P27 式）；
2. **一条细状态线**：阶段（预填充/逐 token/完成）+ 速度，替代整条流水线卡；
3. 其余（Debug、Sampling Inspector、采样显微镜、3D 柱林、此刻卡）全部收进**按需下潜**：右侧一列图标或「专业视图」开关，点开才占屏；
4. 运行结束才展开完成态复盘（现有思路地图/没走的路保留）。

原则：专业面板一个都不删，但**默认不同时在场**；Explorer 第一眼永远只有一条正在发生的故事。

## 7. 基础质量债（本次一并偿还 + 教训入流程）

**5.1 自绘下拉/浮层组件规范**（反面案例 B：Agent 规划原生 select 展开时系统样式压在 3D 场景上）
- 全站禁用原生 `<select>` 弹出层。现存 3 处：ObservePage 规划模型（L2736）、ModelSelect 内部（L257）、ArchiveCards 筛选（L52）。
- 统一自绘 `Dropdown`：与既有浮层同气质（rounded-xl · border-obs-line · bg-obs-2 · shadow-float · backdrop-blur），键盘可达（↑↓/Enter/Esc）、aria-expanded/listbox 语义、点击外部关闭、向上/向下自适应展开。
- 复用现有「更多 ▸」浮层的视觉件，不引新依赖。

**5.2 Agent 规划过程舞台化**（反面案例 C：规划子运行期间主舞台空白，只有一行小字）
规划是最该被看见的过程。规划子运行期间主舞台呈现（全部真实数据）：
- 「它在先给自己写计划」标题 + 规划模型徽章（同模型/接力交棒）；
- 计划文本**逐字流出**（规划子运行本身就是一次真实生成，有自己的 token 流——直接播它，而不是等结果）；
- 完成后：计划全文卡 + 耗时 + 「按此计划开始作答」过渡；失败如实呈现 ok:false，静止不装饰。
- 接力（model_handoff）时显示先卸后载的真实阶段。

**5.3 交付流程新增硬规则**（写入 `AOKS/PRODUCT-DELIVERY-WORKFLOW.md`，防止重犯）：
> 任何交互组件必须连同其**全部状态**一起设计并验收：默认 / hover / 展开 / 加载中 / 失败 / 空态 / 禁用。
> 只交付「关着的样子」不算完成；展开态压在什么背景上、加载中主舞台放什么，属于设计本体而非细节。

## 8. 宪法三层级收敛（治理架构，防止原则无限膨胀）

此后宪法不再线性追加原则，而是收敛为三层级；新增原则必须归入其一，归不进 = 不新增：

| 层级 | 回答 | 归位 |
|---|---|---|
| **价值层（Why）** | 产品为什么存在，对真实性与意义的要求 | 使命句、Evidence First、P25、P26 |
| **认知层（How people understand）** | 用户如何建立正确心智模型 | P27、P28、五问检验、Narrative Grammar |
| **交互层（How the interface behaves）** | 界面具体行为规范 | 直接操纵、无隐藏状态、词即入口、三态骨架、P24 视觉红线 |

落地方式：`E5-VolumeI-产品宪法.md` 增加三层级目录索引（原则原文不动、只归位），合规速查表按三层重排。未来 Agent/MCP/工具调用/长上下文/attention 导出等能力全部归入既有层级——**原则随能力保持稳定，不随功能增加**。
