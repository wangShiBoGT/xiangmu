> 对应 `docs/总体规划-锚点.md` 第 0–4 层。
> 写法约定：每层不复述定稿结论，只写**新的思考增量**——
> ① 三类真实用户的逐帧走查（在哪一秒流失、为什么）；
> ② PM 自我攻击（挑战已达成的共识、被否决的备选方案与理由、可证伪的失败判据）；
> ③ UI 设计决策（版式/层级/动效预算/移动端，具体到可执行）；
> ④ 这一层最可能死掉的方式。
> 所有引用的数据与代码均为项目真实现状（229 步 demo trace、145 项测试、现有组件名）。

## 先立三个用户，后面每层都用他们走查

| 画像 | 代表 | 进站动机 | 致命弱点 |
|---|---|---|---|
| **U1 好奇路人** | 你的那位同事（真实发生：看完演示只问「干嘛呢」） | 别人发来链接，随手点开 | 8 秒耐心；不认识「token」「概率」；手机打开的概率 >50% |
| **U2 AI 从业者** | 用过 ChatGPT API、调过 temperature 的工程师 | 想看看「又一个可视化工具」有什么新的 | 见过 logprobs，阈值极高；一眼扫到不严谨（如把 top-k 熵冒充全词表熵）立刻关页并记住你不可信 |
| **U3 研究/内容型用户** | 写 AI 科普的博主、做 prompt 评测的人 | 找能引用、能截图、能复现的素材 | 需要的不是「看」而是「引用背书」：口径、seed、导出、复现步骤缺一不可 |

**一个必须诚实面对的事实**：这三类人要的东西互相冲突。
U1 要少（一句话一个按钮），U2 要准（口径、边界、原始数据），U3 要全（导出、复现、来源）。
前四层的本质就是**用"层"来调解这个冲突**：同一屏内不调和，用递进深度调和。
这也是 progressive disclosure 在本产品的真正含义——不是"逐步展示功能"，而是"逐步切换服务对象"。

# 第 0 层 · 宪法

## PM 自我攻击：四条原则里哪条最可能变成自欺？

**P1（Evidence First）最脆弱的地方不是"说谎"，而是"用真数据讲误导性故事"。**
我们已经差点犯一次：首屏切片只放 20.08% vs 20.08% 两行，数字全真，结论全歪
（暗示二选一，实际其余候选还有 59.84%）。评审 R1 补了"切片上下文"规则，但要承认：
**这类错误无法穷举，规则只能事后追加。** 所以宪法层真正需要的不是更多规则，而是一个流程：
每个批次上线前，指定一个"对抗性读者"角色（拿 U2 的眼光）专门找"真数据假故事"。
本项目里这个角色由评审文档承担（`定稿评审记录.md` 就是第一次执行记录），以后每批次必须产出一份。

**P4（每次点击有兑现）在数学上有一个隐藏成本没人讨论过：兑现链是乘法不是加法。**
假设每次点击的兑现率是 90%，五次点击后只剩 59% 的用户还觉得"这产品说到做到"。
这意味着 P4 的检验不能只查单个按钮，要查**最长点击链**（首屏按钮 → 暂停帧 → 候选点击 →
回看犹豫步 → 装载 trace → 跑自己的 prompt，共 6 级）。链上最弱的一环决定整体印象——
目前已知最弱环是"跑自己的 prompt"：模型下载数百 MB，首 token 可能等 10 秒以上。
这不是文案能解决的，是**预期管理设计**问题（见第 2 层 UI 节）。

**被否决的备选**：曾考虑把四原则做成界面上的公开承诺（页脚"我们的原则"）。
否决理由：原则是内部过滤器，公开宣示反而制造攻击面（用户拿着原则找茬每一句文案），
且 U1 根本不读。原则的正确曝光方式是让用户"感觉到"而非"读到"。

## 可证伪的失败判据

- 若连续两个批次的评审记录找不出任何一条"真数据假故事"，说明对抗性评审在走过场（不可能没有）。
- 若 A8 数据显示 6 级点击链的第 3 级流失 >70%，P4 在实践中未成立，需回头审链条而非加功能。

# 第 1 层 · 首屏叙事

## 用户逐帧走查（这是定稿文案没做过的推演）

**U1 好奇路人，手机，微信内置浏览器，第 0–10 秒：**

```text
0s   打开。首屏必须 <1s 可读，否则已经死了 30%。
     现状风险：观察页字号体系为桌面设计（11–14px 为主），手机上谜题句若不重排会小到没有冲击力。
1s   读到「为什么同一句问题，AI 每次回答都不一样？」
     ⚠ 批判：这句话对 U1 有一个隐藏前提——他注意过答案不一样。
     没深度用过 AI 的人可能从没注意过。此时这句话不是谜题，是陈述。
     对策（已想过三个备选，见下）:谜底句必须立刻接住,
     「因为这个答案，曾经差点变成另一个答案」不依赖用户的既有观察也能制造悬念。
3s   看到切片 20.08 / 20.08 / 59.84。
     ⚠ U1 不看数字看形状。切片必须是"两根几乎等长的条 + 一根更长的灰条"，
     数字是给 U2 的，条形是给 U1 的。如果做成表格，U1 流失。
5s   按钮「亲眼看这一刻 →」。
     手机上按钮必须在首屏折叠线以上。若需滚动才见按钮，移动端转化预计砍半。
8s   点击。之后的体验属于第 2 层。
```

**U2 从业者，桌面，第 0–30 秒：**

```text
0s   扫标题，内心："哦，又一个 token 可视化。"
2s   看到切片下的小字「其余所有候选合计 59.84%」——这行字是给他的暗号：
     "这个产品知道 top-2 不等于全部"。这行小字对 U1 无意义，对 U2 是信任的开关。
5s   他不点大按钮，他会找"数据从哪来"。所以切片必须可展开原始 top-8 + 采样参数
     （seed 473055871 / T 0.7 / top-p 0.95），缺这个展开，U2 判定"营销页"离开。
30s  若展开里看到 P(vocab) 口径声明，U2 的行为会变化：开始主动测试边界（长 prompt、
     换模型）——他从访客变成审计者，这是好事，审计通过的 U2 是最强的传播者。
```

**U3 内容型用户**：不走首屏主线，直接找「能不能把这个犹豫点截图/导出」。
首屏切片右下应有极低调的「查看原始数据」入口，通向 `.aitrace` 视图——已有能力，只缺入口。

## PM 自我攻击

**挑战共识 1：谜题句真的是最优解吗？** 我们在讨论中快速收敛到「每次回答都不一样」，
但有两个未被认真比较的备选：

| 备选 | 优点 | 为什么最终不用 |
|---|---|---|
| 「AI 写下这个字之前，考虑过 8 个别的字」 | 不依赖用户既有观察，直接指向切片 | 「考虑」是拟人陈述，违反 P2；改成中性表述后失去冲击力 |
| 「这个答案差 0.003% 就是另一个答案」 | 数字冲击力极强 | 未做 C3 双结局前，"就是另一个答案"证明不了（P1）；且 U1 对百分比无感 |

保留谜题句的真正理由不是它完美，而是它**唯一同时满足**：锚在已有经验（对至少一半用户成立）、
可被切片证明、不含拟人断言。**但要写下失败判据**：A9 测试中若 10 人里 ≥4 人对谜题句无反应
（追问"什么叫每次不一样？"），立即启用备选一的中性化变体，不恋战。

**挑战共识 2：首屏放真实切片，意味着首屏依赖 demo trace 加载。**
`demo.aitrace.json` 110KB（gzip 26KB），可接受；但若未来换成更长 trace，首屏数字就有延迟。
决策：切片数字构建时预计算嵌入 HTML（A10 的"运行时计算"指构建时从 trace 文件计算，
不是浏览器运行时等待 fetch）——这是定稿文档没写清的实现歧义，在此钉死：
**首屏切片必须 0 网络依赖可渲染，数字来源仍是真实 trace 文件，构建脚本从中提取。**

**挑战共识 3：A8 行为 trace 的伦理一致性。**
我们的口号是"数据不出设备"，那么 A8 即使匿名本地也必须做到：默认本地、绝不上传、
设备页可见可删——并且**它自己也要过 P1**：漏斗展示时注明样本只有本机访客。
若未来想要真实多用户数据，那是另一个需要用户明确同意的功能，不许悄悄合并进 A8。

## UI 设计决策（可直接执行的规格）

- **版式**：首屏纵向四段（谜题/谜底/切片/按钮），最大宽度 680px 居中；
  谜题句字号桌面 clamp(28px, 4vw, 40px)、手机 24px，行高 1.35；谜底句退一级（16/14px，ink-2 色）。
- **切片组件**：三根横条（两根等长强调色、一根灰），条内左端 token 文本、右端百分比；
  高度合计 ≤ 120px；hover/tap 展开原始 top-8 + 参数（复用 SamplingInspector 的行样式，不新造视觉语言）。
- **动效预算**：首屏总动效 ≤ 1 处——切片两根等长条入场时从 0 长到 20.08%（600ms, ease-out），
  制造"并驾齐驱"的一瞬。其余全静态。理由：动效是稀缺注意力货币，花在证据上而不是装饰上。
- **移动端**：四段必须在 100vh 内完整可见（iPhone SE 668px 可视高度为下限）；
  按钮 min-height 44px；3D 仪器在手机上默认不加载，直接用 SamplingChamber 2D 降级（现有 fallback 机制）。
- **深色**：观察页现为深色体系（bg-obs），首屏若保持浅色会产生"进门变天"的割裂——
  批次 1 需做一次明确决策：**首屏改为同一深色体系**，代价是 LandingHero 现有浅色资产重做，
  收益是首屏→演示零割裂（P4 的视觉版本）。此项工作量并入 A1/A7。

## 这一层最可能死掉的方式

不是文案不好，而是**加载顺序失误**：若 Three.js/ONNX 任何一个混进首屏关键路径，
U1 在白屏第 2 秒离开，后面一切不存在。验收必须含：慢速 3G 模拟下首屏文字 <2s 可读。

# 第 2 层 · 存量能力（兑现层）

## 用户逐帧走查：从按钮点击到"第一次干预"

```text
U1 点「亲眼看这一刻」：
+0s   直达犹豫点暂停帧（A4 快进模式）。
      ⚠ 批判定稿方案：完全跳过前段播放是错的——没有"看着它一个字一个字写"的 5 秒铺垫，
      暂停帧的"停"就没有戏剧性。正确节奏：快进播放前段（约 3–4 秒扫过 67 步，可视化上
      是 trace 快速生长），在犹豫点急停。"快"本身成为铺垫，"停"才有重量。
      此为对 A4 的实现修正，锚点内容不变，节奏参数在开发时调优。
+5s   引导卡出现（底部固定，上批次已修好任何窗口可见）。
      U1 读到「本身 20.08% vs 这个词 20.08%」——此刻他在首屏看过同样的数字，
      认知闭环："刚才那个切片就是这里"。这是两层之间最重要的一次呼应，
      UI 上切片与暂停帧候选榜必须使用完全相同的视觉样式（同组件），让用户"认出来"。
+10s  他面前有两个动作：点候选行（探索）或点「继续看它写完」（顺从）。
      A8 要分别记录这两个选择——它们是 U1 与 U2 的天然分类器。
```

**U2 在这一层的关键时刻**是跑自己的 prompt：模型下载 300MB+、WASM 降级后首 token 可能 >15s。
现有 BreathingWait 已经做了"诚实等待"（不假进度、≥10s 显示真实已等时长），
但缺一个关键信息：**等待时教学**。这 15 秒是产品唯一一段用户被迫注视屏幕又无事可做的时间，
应展示"接下来你会看到什么"（一张标注过的 trace 示意，用 demo trace 真图不是画的）——
把死时间变成预期建设。此项作为批次 2 的一个小锚点提出（不进批次 1，控制范围）。

## PM 自我攻击

**挑战共识：我们说"可玩性层已建成"，这是工程视角的真，产品视角的假。**
能力都在（Branch/对比/档案/规则），但走查一遍会发现它们是**并列陈列**而非**旅程编排**：
跑完一次生成后，界面同时给出分岔树、三个方向按钮、时间线、导出、分享卡——
对 U1 这是六个出口的迷宫。真正的旅程应该是单线：
生成完成 → 收束卡只给一个主出口（「这个回答有 N 个犹豫点，看最险的一个」）→
看完犹豫点再给分支（「换一个字会怎样？」→ Branch）。
**每屏一个主动作，其余全部降级为次要链接。** 这是批次 2（C1）文案审查之外要一并做的
信息架构收敛，工作量并入 C1，在此记录设计原则：**主动作唯一性**。

**被否决的备选**：曾讨论过"新手引导浮层"（第一次进入时高亮各功能）。
否决理由：引导浮层是信息架构失败的补丁；且与 P4 冲突——教学不是兑现。
正确解法就是上面的单线旅程。

## 这一层最可能死掉的方式

WebGPU 兼容性长尾。已有降级链（WebGPU→WASM→更小模型→明确报错），但降级后的体验
（1.5B 模型 WASM 下 <2 tok/s）对 U1 就是"卡死了"。诚实的做法：降级发生时明确告知
"你的设备用 CPU 运行，速度约为 GPU 的 1/10，看录制示例不受影响"——把 demo trace 回放
作为低配设备的一等公民体验，而不是安慰奖。

# 第 3 层 · Evidence First 界面化

## 用户走查：谁真的会点开"陈述"？

诚实的预测：**U1 几乎不会点**。可展开陈述（C2）的直接用户是 U2/U3。
那为什么还值得做？因为它对 U1 的价值是**氛围性**的——满屏可展开记号传递
"这里每句话都敢被查"，即使从不点开。就像论文里的引用标注，读者不点，但没有就不信。
所以 C2 的验收不该用点开率衡量（预设它很低，<5% 都正常），
该用 A9 后续测试中的信任语言衡量（"感觉这个网站比较真/专业"之类的定性反馈）。

## PM 自我攻击

**挑战共识：C3（犹豫点双结局）比看起来危险。**
两个候选各自续跑，可能出现三种结果：
1. 两个结局明显不同 —— 完美，故事成立；
2. 两个结局殊途同归（几个 token 后回到同一表述）—— 这其实是**更深刻的发现**
   （模型的收敛性），但对期待"蝴蝶效应"的用户是反高潮；
3. 某一支跑崩（重复、乱码）—— 尴尬但真实。
产品必须三种都接住：结果 2 的文案预案是「这次分岔在 N 步后重新汇合——AI 的用词会抖动，
观点常常稳定」（这本身就是一条可展开陈述）；结果 3 如实展示并标注数值异常。
**不允许**只挑结果 1 的案例做 demo——那是用真功能做假叙事，违反 P1 的精神。

**挑战共识：C2 组件的粒度陷阱。**
"每句陈述可展开"若执行到字面，页面会布满下划线记号，视觉噪音反而稀释信任。
规格收敛：每屏可展开陈述 ≤ 3 处，只给**承载结论重量**的句子
（统计断言、比较断言、机制断言），描述性文字不加。宁缺勿滥。

## UI 设计决策

- 可展开记号：细虚线下划线 + 尾部微型 ⌄，颜色用 ink-2（不抢主文本）；
  展开为原位向下推开的面板（不是弹窗——保持"证据就在陈述脚下"的隐喻），内嵌对应步的
  SamplingInspector 行或统计明细，带「在完整 trace 中查看」跳转。
- 双结局页：左右双栏（复用 DualTraceChannel 的对照布局），顶部共享的分岔点切片，
  分岔以下两栏文字逐 token 对齐渲染，首个不同 token 高亮——视觉重心是"从同一点长出两棵树"。

## 这一层最可能死掉的方式

做成"给评审看的功能"：团队自己都不用可展开陈述，只在演示时点两下。
防死法：C1 审查产出的每条结论句改写，必须同时登记它绑定的 TraceFocus——
登记不了的说明那句话本来就不该说（宪法的自我执行）。

# 第 4 层 · Benchmark 体系（D1–D6）

## 为什么第 4 层的性质与前三层根本不同

前三层服务"一个用户看一条 trace"；第 4 层第一次引入**跨 trace、跨模型、跨用户的比较**——
比较必然产生排名，排名必然产生利益（哪个模型"好"），利益必然吸引作弊与误读。
**所以第 4 层的核心设计对象不是图表，是"误读的成本"。** 这是前三层不存在的问题。

## 用户走查

- **U1** 只会消费一句话结论（"我的电脑跑这个模型比 80% 的设备快"——本机体检报告已做）。
  他不需要 Benchmark Center，别为他做。
- **U2** 想要的是"我改了 prompt/参数，分数变了多少"——即 D3 行为 Benchmark 的回归测试用法。
  这是第 4 层最高频、最正当的使用场景，应作为 D3 的设计中心：
  **Benchmark 首先是"自己和自己比"的工具，其次才是"模型和模型比"的排行**。
- **U3** 想引用："在 XX 规则包下，模型 A 的规则命中率为 Y%"——他需要规则包版本号、
  固定 seed 集、可复现命令。没有这三样，引用就是谣言的种子。

## PM 自我攻击：第 4 层最可能死掉的三种方式

1. **死于混层**：官方分数（D1 引用）和本机实测（D2）出现在同一张表里没有视觉隔离，
   被截图传播成"XX 模型本机跑分超过 GPT"。防死法：两层数据永远不同表、不同色、
   引用层每个数字带来源角标；这不是美观问题，是 P1 在第 4 层的生死线。
2. **死于 DSL 野心**：D4 自定义规则包若一开始就设计通用 DSL，会做出一个没人学得会的
   小语言。收敛：V1 规则包 = 现有 `rules.ts` 规则结构的 JSON 导出/导入 + 命名 + 版本号，
   零新语法；DSL 等到有 ≥10 个真实用户创建 ≥50 条规则后再从真实用法中归纳（D5 之后）。
3. **死于统计幼稚**：单次 run 的规则命中数当 Benchmark 分数，seed 一换分数就变，
   U2 一眼看穿。D3 的每个分数必须是多 seed 重复的分布（中位数 + 极差），
   这直接决定 D3 的数据模型：`score = {seeds[], values[], median, range}`，不是一个数。
   算力成本（同题跑 5 个 seed）在本地推理下是真实约束——这正好是产品的差异化：
   本地零成本重复，云 API 做不起的事我们免费做。

## 递进关系的真实含义

第 3 层教会用户"一条陈述背后是一次核验"；第 4 层把它规模化成"一个分数背后是一组核验"。
若第 3 层的可展开陈述没有养成用户的核验直觉，第 4 层的分数就会被当成又一个营销数字——
**所以第 4 层的成败一半取决于第 3 层的执行质量**，这是批次顺序不可对调的真正原因。
