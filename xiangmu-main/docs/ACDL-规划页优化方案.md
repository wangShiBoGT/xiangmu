# 规划页（Agent 规划 · 运行中界面）优化方案

> 状态：方案稿 · 待创始人拍板后开工（本文档只做设计，不含代码改动）
> 范围：显微镜层「运行中」的规划/检索子运行阶段 + 主生成阶段的整体布局与话术
> 依据：AVP 协议（docs/architecture/AVP.md）、产品宪法 P27–P31、2026-07-25 创始人反馈截图

---

## 一、要解决的问题（来自真实反馈）

1. **掌控感缺失**：运行时用户「看着不觉得能掌控一切」——信息平铺，主次不清，控制散落。
2. **样式没有好好设计**：DEBUG 条、阶段带、协作流、右栏各自为卡，风格与密度不一。
3. **区域运用不合理**：大面积 3D 舞台空转，关键解释（规划文本、交接）挤在小卡里；右栏在无 token 时只有「等待第一个词…」两张空卡。

已修的两个 BUG（不在本方案内）：旧存档覆盖新任务；TeamFlow 与 3D 仪表叠加。

## 二、设计原则

- 一屏一问：规划阶段这一屏只回答「AI 团队正在做什么、到哪一步了」。
- 区域即角色：每个屏幕区域固定承担一种职责，运行全程不跳变。
- 掌控感 = 可见（在哪一步）+ 可控（随时暂停/断点/收起）+ 可预期（下一步是什么）。
- 真实优先：没有数据的区域诚实留白或不渲染，不放空壳卡。

## 三、目标布局（规划/检索子运行阶段）

```text
┌─────────────────────────────────────────────┬──────────────┐
│ A 控制台条（一张卡，常驻顶部）                  │              │
│   左：Run 身份（模型·后端·T·seed）             │  D 右栏       │
│   中：任务阶段（检索✓→规划●→作答○→完成○）      │  （规划阶段） │
│   右：⏸暂停 ◉断点 收起专业面板                 │  Planner 侧卡 │
├─────────────────────────────────────────────┤  · 规划模型   │
│ B 主舞台 = TeamFlow（唯一主角）                │  · 已生成字数 │
│   问题一行 → TEAM 名册 → Worker Pipeline       │  · 实时耗时   │
│   规划文本流式区（大、可读、自动滚动）          │  · 交接预告   │
│   Artifact / 交接原因                          │              │
├─────────────────────────────────────────────┤              │
│ C 记录台（composer，含停止按钮）               │              │
└─────────────────────────────────────────────┴──────────────┘
```

要点：

- **A 控制台条**：已在本轮实现（合并卡）。后续统一 done/running 两态视觉，按钮样式与 chips 同一套语法。
- **B 主舞台**：TeamFlow 占满主列宽度（当前偏窄居中）。规划文本区高度上限 ~40vh、内部滚动、`<think>` 段折叠为「推理中…」摘要行，点击展开原文。
- **C 记录台**：运行中输入框禁用态要有明确视觉（当前只是变灰），停止按钮旁加「停止并保留已生成」文案 tooltip。
- **D 右栏**：规划阶段不再显示空的 Sampling Inspector（等待第一个词…）。改显示 Planner 侧卡：规划模型、真实耗时读秒、已流出 token 数、下一步交接给谁；首个正文 token 出来后右栏切回 Sampling Inspector。

## 四、主生成阶段（token 开始后）

- B 主舞台切换为仪表/正文；TeamFlow 收敛为顶部 TeamPanel 名册条（已实现，保留）。
- 切换要有过渡：TeamFlow 折叠动画 → 名册条落位，避免整屏跳变（`prefers-reduced-motion` 降级为直接切换）。
- 控制台条 A 不动、右栏 D 切 Sampling Inspector——三区职责全程不变。

## 五、话术清单（规划阶段）

| 现状 | 改为 |
| --- | --- |
| 工作中（Planner 徽章） | 正在制定计划 · 第 N 秒 |
| 等待中（Executor） | 等待计划 · 拿到后开始作答 |
| 17.8 s · 真实生成中 | 已思考 17.8 秒 · 计划逐字流出（真实生成） |
| 团队成员、交付物与交接原因均来自本次真实子运行，全部记入 trace | 保留，字号不变，仍在卡底 |
| 等待第一个词…（右栏） | 删除该空卡（按上文 D 改） |

## 六、验收标准

1. 规划阶段一屏内能回答 AVP 四问（谁在工作/为什么/交了什么/到哪了），无需滚动。
2. 运行全程 A/B/C/D 四区职责不变，无元素叠加、无空壳卡。
3. 暂停/断点/收起三个控制常驻可见、可点。
4. `<think>` 长文不撑爆主舞台；展开/收起有 aria 语义。
5. 全部信息来自真实事件；无数据的阶段/卡诚实缺席。
6. tsc / lint / 全部测试 / build 全绿；本机 WebGPU 复核通过。

## 七、实施拆分（拍板后按序开工）

- P1 右栏规划态 Planner 侧卡（替换空 Inspector）
- P2 主舞台 TeamFlow 加宽 + 规划文本区滚动/折叠
- P3 阶段切换过渡动画（reduced-motion 降级）
- P4 话术替换（上表）
- P5 记录台禁用态与停止按钮文案
