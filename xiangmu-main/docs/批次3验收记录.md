# 批次 3 验收记录 · 双结局 + 行为基准起步 + 规则包 V1

> 对应锚点：C3（双结局三种结果全接住）、D3（多 seed 分数分布）、D4（规则包 V1 零 DSL）。
> 验收方式：tsc / oxlint / vitest（172 通过，+14）/ build + 云端页面逐点走查（无录屏）。

## C3 · 双结局

- `src/lib/dualEnding.ts`：确定性文本规则把两条真实续写分类为三种结果——
  不同（公共后缀 <12 字）/ 殊途同归（末尾 ≥12 字相同，预置文案「用词会抖动，观点常常稳定」）/
  退化（结局 <6 个非空白字符或同一字符连续重复 ≥12 次，如实展示依据）。
  分类由数据决定，不挑蝴蝶效应案例（P1）。5 个单测覆盖三分支 + 空白归一。
- `DualEndingCard`（ObservePage）：查看任一分支时自动出现——分岔处原选/改选概率、
  两段结局并排、判定依据一句话；整卡用 EvidencedClaim 包装，来源
  `root/children[].trace.steps[].text`。入口复用现有出生卡「改选候选」真实续跑，无新推理路径。

## D3 · 行为基准首期（自己和自己比）

- `src/lib/behaviorBench.ts`：分数模型定死为分布 `{values, seeds, median, range}`，
  组内 <2 次运行不产生分数（单 seed 单值不构成基准）；只在严格可比较组
  （compatKey：模型·prompt·参数·后端）内比较；首个指标 rule-hit-rate =
  每 100 token 的规则命中数，统一用 Core Rules 求值保证组内可比。5 个单测。
- ArchivePage 新增「Behavior Bench · 自己和自己比」卡：每组一条 EvidencedClaim
  （中位数 + 极差），展开逐 seed 数值，来源登记为
  `存档内同可比较组 runs × evaluateRules(steps, CORE_RULES)`。

## D4 · 规则包 V1（零新 DSL）

- `src/lib/rulePack.ts`：`aiobs.rulepack/1` 信封 = name + version + exportedAt + rules，
  复用现有 `validateRuleset`；裸 Rule[] 数组仍可导入（向后兼容）。4 个单测
  （往返一致 / 默认回退 / 裸数组 / 三类人话错误）。
- RulesPanel：命名输入 + 「导出规则包 / 导入规则包」，导入成功显示包名与规则数。
