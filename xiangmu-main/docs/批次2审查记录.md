## C2 · EvidencedClaim 组件

- `src/components/EvidencedClaim.tsx`：陈述句细虚线下划线 + ⌄，点击原位展开证据明细；
  `source` 必填（证据字段路径）= 登记制的机制化——写不出来源的句子无法使用本组件。
- 首个落地实例：完成态摘要（CompleteSummary）的犹豫点陈述。
- 单测：默认收起 / 展开显示证据与来源 / onInspect 跳转 / 无 onInspect 不出入口。

## 旅程收敛 · 完成态唯一主出口

- 生成完成后摘要卡的判读行改为唯一主出口：
  「这个回答有 N 个犹豫点（前两名候选概率差不足 5%），最险在第 X 步」
  —— 展开 = 差距最小的前 8 步（逐行可跳转），来源 `steps[].topk[0..1].prob`。
- 无犹豫点时退回原「候选分布最分散的步骤」入口（最高熵步）。
- 口径统一：新增 `src/lib/closeSteps.ts`（computeCloseSteps/formatGap），
  演示收束卡与完成态摘要共用同一实现，消除两处重复计算。

## C1 · 全站文案审查表

审查范围：src 下全部用户可见文案（组件 + lib 中的 detail/title 字符串）。
检索词：拿不定主意 / 改变主意 / 犹豫了 / 想 / 认为 / 决定 / 偏好 / 喜欢 / 聪明 / 纠结。

| 句子 | 位置 | 处理 |
| --- | --- | --- |
| 「这里 AI 最拿不定主意，候选最分散」 | ObservePage 演示注释条 | 改写 →「这里候选分布最分散（本次 trace 的最高熵步）」 |
| 「犹豫点」各处 | 多处 | 保留：索引名用法，紧随其后均有数值定义（差距 <5%） |
| 「差点变成另一个答案 / 差点选的字」 | 首屏、暂停卡、收束卡 | 保留：可点开到真实 top-2 概率，Evidence First 合规 |
| 「思考 / 深度思考」各处 | ChatMessage、TokenText 等 | 保留：指 `<think>` 协议段的领域术语，非心理断言 |
| findings.ts 各 detail | lib/findings.ts | 保留：全部携带 recIds/step/source，可一跳核验 |
