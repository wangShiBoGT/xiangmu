# AODL · Layer 1 · Cognitive DNA（认知 DNA）

> AODL 六层认知栈见 `00-AODL-索引与认知栈.md`。本篇是 **Layer 1（认知语言）**，
> 位于 Layer 0 世界观之下、Layer 2 视觉语言之上——它决定视觉、交互、系统一切下层的服务对象。
>
> 前面所有篇章（含四卷宪法、Visual DNA）都在回答一个问题：**产品应该是什么。**
> 本篇回答一个过去没人系统回答过的问题：
>
> **当人类第一次观察 AI 时，用户脑子里，应该一步步发生什么？**
>
> 这是学习科学，不是 UI。产品视角是「可信/克制/透明」；用户视角是「我什么时候开始相信、开始探索、
> 开始明白」。本篇立的不是产品性格，是**用户认知的建立时序**——这也是 AODL 最难被复制的一层。

---

## 0 · Cognitive DNA 与 Visual DNA 的区别

| | Visual DNA（Layer 2） | Cognitive DNA（Layer 1） |
|---|---|---|
| 主语 | 产品 | 用户 |
| 回答 | 产品是什么气质 | 用户脑子里发生什么 |
| 单位 | 性格轴（可信/克制…） | 认知时刻（信任建立/探索启动…） |
| 检验 | 同一只手测试（看得出） | 认知验收（用户说出「原来…」） |
| 谁服从谁 | 服从认知层 | 认知层是源头 |

一句话：**Visual DNA 决定"它看起来像同一只手"，Cognitive DNA 决定"用户的理解一步步长出来"。** 设计的终点不是像素对味，是**用户脑子里真的建立了对 AI 的认知**。

---

## 1 · 六条认知原则（Six Cognitive Principles）

每条原则是一个「X Before Y」的**时序约束**：认知有先后，次序错了，认知不发生。每条附「触发时刻 / 如何设计 / 判据 / 反模式」。

---

### 原则一 · Question Before Knowledge（先有问题，再给知识）

**认知命题**：知识只有落在一个已经打开的问题上才会被吸收；先给定义、后给现象，定义会被当噪音略过。

**触发时刻**：用户看到一个反常现象（同一个问题两次答案不同 / 前两个候选只差 0.4%），**先困惑**——这一刻问题被打开。

**如何设计**：每个入口只提出问题，不解释原理；名词（temperature/entropy/seed）永远出现在用户**已经看到现象之后**（承 P3）。

**判据**：删掉界面上所有名词解释，用户是否仍被现象本身勾住、产生「为什么」？是→问题在先；否→你在教科书，不在制造好奇。

**反模式**：首屏先讲「什么是温度采样」，再展示效果——把课堂搬到了好奇之前。

---

### 原则二 · Evidence Before Belief（先有证据，再有相信）

**认知命题**：信任不是被告知的，是被验证出来的。用户相信一个数字，不是因为它「看起来专业」，而是因为他**发现自己能核对它**。

**触发时刻**：用户第一次发现——**任何一句话都可以点开，点开是真数据、带来源路径**。这一刻，信任建立（不是在第一次看到数字时，是在第一次成功下钻时）。

**如何设计**：每个陈述句可下潜到产生它的原始 trace（承 P1/P10）；来源路径常驻；口径与"本测量不包含什么"同版可见（承 P12）。信任是**下钻的副产品**，不是措辞的成果。

**判据**：用户访谈里"我信这个"这句话，出现在他**第一次点开一句话看到证据之后**，而不是出现在他第一次看到漂亮界面时。

**反模式**：用权威排版、大字号、认证徽章制造"看起来可信"——那是 belief without evidence，本产品最忌。

---

### 原则三 · Discovery Before Feature（先有发现，再有功能）

**认知命题**：用户不"学习"功能，用户"发现"能力。被教会的很快忘，自己发现的记很久。

**触发时刻**：用户在使用现场**自己撞见**下一个能力（发现列表行能点、发现还能换 seed、发现字能改），而不是被 onboarding 浮层告知。

**如何设计**：教学寄生在控件上（kbd 小方块、placeholder 提示，Lovart 式现场教学，承 Vol III §1.5/§2.1）；禁止新手引导浮层、功能巡演；每个能力在"用户正好需要它"的位置第一次显形。

**判据**：产品能否零 onboarding 上手？用户第一次用到某能力，是"我发现了"还是"它教了我"？前者→Discovery；后者→退回。

**反模式**：首次访问弹出"3 步了解本产品"的引导层。

---

### 原则四 · Layer Before Density（先有分层，再谈密度）

**认知命题**：认知带宽有限，一屏超过三层重要性，理解就开始排队（承 Vol II §1）。透明不是"一次全给"，是"要多深给多深"。

**触发时刻**：用户在**自己选择**下潜时才遇到高密度——第一层永远低密度叙事，原始 JSON 只在主动点到底时出现。

**如何设计**：三级下潜语法（陈述句→证据卡→原始层，承 P10/Vol III §1.2）；首层低密度，高密度只在下潜后（承 Vol II §2.4 不能学）；每层可独立读懂、可自愿停下。

**判据**：普通用户止步第一层是否已获得完整不困惑的叙事？研究者能否一路下潜到 JSON？两者缺一即失衡（不够透明 / 透明做成了复杂）。

**反模式**：为了"显得透明"把全量张量、全部参数铺在首屏——那是拿密度冒充透明。

---

### 原则五 · Memory Before Novelty（先接旧知，再给新知）

**认知命题**：新概念只有挂在用户**已经知道的东西**上才站得住。孤立的新奇是负担，连接的新奇是理解。

**触发时刻**：每引入一个新机制，用户先被唤起一个已有经验，再看到新机制**如何解释那个经验**。

**如何设计**：用日常经验做锚点，再引出机制——
- 旧知「AI 每次回答都不一样」（人人经历过）→ 新知「换个 seed，这一步采样到了另一个候选」（Replay/Branch）。
- 旧知「它好像忘了前面说的」→ 新知「该内容已超出上下文窗口（第 N token 之前）」。
每个新名词都从一句"你早就见过的现象"进入（承第三章改写范式）。

**判据**：每个新概念旁边，能否指出"它连接的是用户哪一条已有经验"？指不出→这是悬空的新奇，会被遗忘。

**反模式**：直接抛出"entropy 是 token 概率分布的香农熵"，不先唤起"它这一步好像很犹豫"的经验。

---

### 原则六 · Prediction Before Confirmation（先让预测，再给验证）

**认知命题**：这是认知留存最强的机制——人先**做出预测**、再看到结果，无论对错，那个知识都被牢牢刻下（预测误差是学习的燃料）。只被动看结果，学习几乎不发生。

**触发时刻**：每一次关键点击**之前**，用户心里先有一个猜测；点击**之后**，产品给出验证。

**如何设计**：在会产生反直觉结果的操作前，轻量地邀请一次预测，再揭晓——
- 换一个 seed 重跑前：「你猜这一步会不会变？」→ Replay 揭晓。
- 改一个字之前：「你猜后面会分岔多远？」→ Branch 揭晓。
- 调温度之前：分布条先静止，滑动瞬间联动重算（因果即时可见，承 Motion Bible §3.1 因果解释）。
邀请是**轻量、可跳过**的（不打断心流，回访者可直接操作），但入口在场。

**判据**：产品是否存在"先猜后验"的时刻？用户能否在结果揭晓时产生"啊——(我猜对了/没想到)"的反应？没有任何预测环节→用户只是在看演示，不是在做实验。

**反模式**：所有结果直接呈现，用户全程被动观看，一次都没被邀请下过判断。

## 2 · 第一次观察 AI 的认知阶梯（The Observation Ladder）

> 这是本篇、也是整个 AI Observatory 最独有的贡献：把"人类第一次观察 AI"拆成一条**认知一步步长出来**的阶梯。每一阶都是一个认知状态的跃迁，由上面某条原则驱动，且**每阶都为下一阶埋好钩子**（承 P4：每次点击赚下一次点击）。

```text
阶 0 · 困惑     看到反常现象（同问两答 / 候选只差 0.4%）        ← 原则一：问题被打开
   ↓
阶 1 · 信任     发现"任何一句话都能点开、点开是真证据"          ← 原则二：信任建立于第一次下钻
   ↓
阶 2 · 探索     发现"原来还能继续往下钻 / 还能换 seed"          ← 原则三：能力被自己发现
   ↓
阶 3 · 因果     亲手改一个字 / 滑一次温度，看见后面整个分岔      ← 原则六：预测→验证，建立因果
   ↓
阶 4 · 复现     同 seed 重放，逐 token 一致                     ← 可复现的真理（P8）：从"我看到"到"可验证"
   ↓
阶 5 · 结论     用户自己说出"原来 AI 是这样"                    ← P15：结论由用户产生，产品不代说
   ↓
阶 6 · 下一个问题   带着新问题回到阶 0（换模型/换条件/换规则包）  ← 观察是复利，不是一次性 Demo
```

**关键认知事实（设计时反复校准）**：
- **信任不建立在阶 0（看到数字），建立在阶 1（第一次成功核对）**——所以"让第一句话可点开"比"让首屏数字更漂亮"重要得多。
- **探索不由 hover 或按钮启动，由阶 2 的"发现还能往下"启动**——所以下钻入口的"可被发现性"是探索的开关。
- **理解不由阅读产生，由阶 3 的亲手操作 + 阶 4 的复现产生**——读十句解释不如自己改一次字看分岔。
- **每一阶都必须为下一阶留钩子**：困惑里埋"可点开"、信任里埋"还能更深"、探索里埋"能不能改"、因果里埋"能不能复现"、复现里埋"换个条件会怎样"。断一个钩子，阶梯就停在那里。

## 3 · 认知验收（Cognitive DNA 的验收方式）

Visual DNA 用"同一只手测试"验收气质；Cognitive DNA 用**认知时刻是否真的发生**验收——不是问"界面对不对"，是问"用户脑子里长出来了没有"。

任取一个真实首访用户，观察/访谈，验四件事：

1. **问题在先**：他是先困惑、后求解，还是先被灌输名词？（对应原则一）
2. **信任的那一刻**："我信这个"这句话出现在他第一次点开证据之后，而不是看到界面时。（原则二）
3. **预测发生过**：全程是否至少有一次"先猜、后验"，并在揭晓时产生了反应？（原则六）
4. **结论由他说出**："原来 AI 是这样"这句话由用户说出，不是页面写出。（P15）

四件事缺一，说明认知阶梯在某一阶断了——定位到断点那一阶，回到对应原则修，而不是去调像素。

## 4 · 与四卷宪法 / Visual DNA 的关系（事实源指向）

本篇**不新造任何交互或视觉规则**——它把散落在四卷里的认知判断，第一次收敛成"用户认知的建立时序"，并新写四卷完全没有的「观察阶梯」。它是 Layer 2 视觉与 Layer 3 交互的**上游源头**：视觉/交互存在的理由，最终都要回到"它服务认知阶梯的哪一阶"。

| 本篇原则 | 对应四卷事实源 | 本篇新增的部分 |
|---|---|---|
| 一 · Question Before Knowledge | P3（好奇先于解释）| 表述为用户侧的认知时序 |
| 二 · Evidence Before Belief | P1（证据优先）、P10（分层披露）| "信任建立于第一次下钻"这一时刻定位 |
| 三 · Discovery Before Feature | P4、Vol III §1.5/§2.1（现场教学）| "发现 vs 学习"的认知区分 |
| 四 · Layer Before Density | P10、Vol II §1/§2.4 | 认知带宽视角的重述 |
| 五 · Memory Before Novelty | Vol I 第三章改写范式（用旧经验引新名词）| 升格为独立认知原则 |
| 六 · Prediction Before Confirmation | Vol I 第五章 Interaction / Motion §3.1 因果 | **四卷未有**：预测误差作为学习燃料 |
| 观察阶梯 | Vol I 第五章五段式（产品语法）| **四卷未有**：五段式的用户认知镜像，逐阶跃迁 |

> 裁决顺序（承 Vol I 第六章）：基本法 > 通则 > 各卷规范 > 个人品味。本篇属"各卷规范"层，负责认知时序，与四卷冲突时以四卷基本法为准；但在 AODL 六层栈内，认知层（Layer 1）是视觉层（Layer 2）与交互层（Layer 3）的服务对象——下层的存在理由必须能回溯到本篇某一认知时刻。
