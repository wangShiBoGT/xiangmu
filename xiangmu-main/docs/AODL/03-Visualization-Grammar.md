## 0 · 本篇为什么必须存在

### 0.1 三份现有规范都没回答的那个问题

| 文档 | 回答的问题 | 失效表现 |
|---|---|---|
| `design-system.md` | 「这个值合不合规」 | 用了体系外的圆角 |
| `02-Visual-DNA.md` | 「这一屏对不对味」 | 每个值都合规，但拼起来不像一个产品 |
| **本篇** | **「这个量该画成什么形状」** | **每个图都合规、也对味，但用户看完说「所以呢？」** |

第三种失效是当前产品最贵的债务，且它**不会被前两份规范的任何一条检查出来**。一张用测量蓝画的、圆角 10px、字号合规、无 Glow 的饼图——逐值全过、气质无瑕——但它依然是错的，因为**饼图不该用来表达概率**。

这就是「用户看不懂」的病灶：不是不够漂亮，不是不够统一，是**图形选型没有制度**。

### 0.2 本篇与前两份的关键区别：依据来自实验，不是品味

`02-Visual-DNA.md` 的七轴是**可检验的性格**（同一只手测试），依据是设计判断。本篇的每条映射必须附**HCI 实验证据或已验证的产品案例**，依据是可引用的对照实验结果。

这条规矩本身就是准入条件：**任何新增的可视化形式，必须能在附录 A 里指出一条支持它的实验或案例；指不出的，只能进候选池，不能进产品。**

理由很实际——审美争论无法收敛，实验结果可以。当有人主张「概率画成旋转发光球更酷」时，本篇的回应不是「我觉得不好看」，而是「CHI 2018 的对照实验显示点阵显著改善决策质量（附录 A-1），发光球没有任何实验支持，且违反 AODL 轴三」。

### 0.3 现状取证（2026-07-26 实测扫描 `src/`）

| 项 | 实测 | 与 audit（2026-07-25）对比 |
|---|---|---|
| 硬编码字号 `text-[Npx]` | **754 处 / 6 种值**（11px×321、12px×212、13px×143、14px×42、16px×21、24px×15） | 半像素档已清除（原 20 种），但**仍是 0 处体系化字阶** |
| 圆角 | 313×`rounded-md` + 31×`full` + 5×`sm` + 4 处单角 | 已靠 `@theme` 别名收敛（原 9 种），**实质改善** |

## 1 · G0 · 第一道闸门：理解，还是感受？

> **任何可视化在动手之前，必须先书面回答：这个图是帮助用户「理解」，还是帮助用户「感受」？**

两者都合法，但**规格、预算、准入条件完全不同**。混淆两者是 AI 产品最常见的错误——把「感受型」的表现手法（3D、粒子、发光、镜头运动）用在「理解型」的任务上，结果既没让人理解，也没让人感受到什么，只是让人觉得「很 AI」。

| | 理解型（Comprehension） | 感受型（Sensation） |
|---|---|---|
| 用户的动作 | 读值、比大小、找异常、下钻 | 建立直觉、感受量级、产生好奇 |
| 成功判据 | 能正确回答一个具体问题 | 能正确复述一句机制 |
| 维度 | 一律 2D | 允许 3D（须过 §4 四门） |
| 动效 | 仅 `m-pointer` / `m-expand` | 允许一次性入场（≤600ms，一屏 ≤1 次） |
| 每屏预算 | 不限（服从 P28 一屏一问） | **≤1 处** |
| 精度要求 | 数值必须可读、可对齐、可下钻 | 允许不精确，但**不允许不真实** |

**G0 硬规则**

1. 每个可视化组件的文件头注释必须写明 `@cognitive-task: comprehension | sensation` 与它服务的那**一个**具体问题。写不出来的组件不上线。
2. 感受型视觉**同屏 ≤1 处**，且必须挂在一个真实事件上（真实犹豫点、真实交接、真实阶段切换），不允许常驻。
3. 感受型**不得承载必读信息**。删掉它，用户仍能完成任务——这是它的准入条件，也是它的定义。
4. 理解型视觉**禁止 3D**，无例外。

### 1.1 认知任务 → 唯一合法形式

这张表是全站强制映射。**左列决定右列，不允许反向选型**（不允许先决定「我想做个 3D」再找理由）。

| 用户来干什么 | 唯一合法形式 | 禁止替代 |
|---|---|---|
| 看具体数字 | 表格（等宽 + `tabular-nums` + 右对齐） | 图形代替读数 |
| 比大小（2–8 项） | 水平条形 | 饼图、雷达图、词云 |
| **看概率 / 可能性** | **Dot Plot（频率框架）** | 饼图、单个百分比裸数字、旋转球 |
| 看一次采样的多种结局 | HOPs Reel（连播真实样本） | 静态分布图独自承担 |
| 看不确定性高低 | 单色明度阶 + 点阵离散度 | **Glow**、抖动指针、面积锥 |
| 看时间变化 / 耗时 | Timeline（横轴向右，宽度 = 真实耗时） | 流程图贴纸、编号步骤卡 |
| 看关系 / 因果 | Flow Graph（DAG，边 = 归因） | 装饰连线、无向连线 |
| 看计算进行到哪 | 流动虚线 → 实线 | Spinner、`...`、「思考中」 |
| **看空间结构 / 感受规模** | **3D**（须过 §4 四门） | 2D 强行示意 |
| 看参数改变了什么 | Morph（同一图形连续变形） | 前后两张图并排 |
| 看硬件能力要求 | 阈值（显存 / RAM / WebGPU 支持） | 「高性能」「旗舰」「较好的」等评价词 |
| 数据不存在 | 诚实空态（缺什么 / 为什么 / 怎么获得） | 骨架屏、占位假数据、永久禁用按钮 |

## 1.2 · G1 · 第二道闸门：动效跟随计算

> **Motion follows computation, not decoration.**
> 会动的必须是**状态**，不是**东西**。

G0 管「这个量画成什么形状」，G1 管「这个形状凭什么会动」。两道闸门并列，都在动手之前过。

### 为什么需要单列一道闸门

`AI_DESIGN_CONSTITUTION.md` 第 7 条已有「Motion Has Purpose」，`design-system.md` §7 已给出三个动效 token，`02-Visual-DNA.md` 轴七已要求每个像素答出观察到了什么。三道防线齐备，但现状仍有 20 组 keyframes、其中约半数是「场面型」（`birth-scene-converge` / `scatter` / `condense`、`scene-storm`、`fission-in`、`pop-in`）。

原因是那三条都在问「**这个动效有没有目的**」，而目的是可以被诡辩出来的——「粒子汇聚表达了候选收敛」听起来就有目的。G1 换一个问法，堵住这条路：

> **不问「它有没有目的」，问「它跟随的是哪一次计算」。**
> 答不出「哪个字段在这一帧变化了、变化前后的值是多少」的动效，一律删除。

「字在飞」和「token 在流」的区别就在这里：前者动的是**已经确定的东西的位置**（计算早已完成，位移纯属表演），后者动的是**尚在推进的状态**（每一帧对应一次真实的采样步）。

### G1 判据（三问，全过才留）

1. **哪次计算？** 这个动效对应 trace 里哪一个事件 / 哪个字段的变化？（答不出即删）
2. **计算停了它停吗？** 计算结束后它必须停。**结束后还在动的一律是装饰。**
3. **它动的是状态还是外观？** 位置 / 缩放 / 旋转 / 模糊属于外观；长度 / 数量 / 明度 / 虚实 / 位置沿轴推进属于状态。

### 该动什么，不该动什么

| 动这个（跟随计算） | 不要动这个（跟随装饰） |
|---|---|
| 线的**虚实**（进行中 → 完成，V4） | 元素飞入 / 滑入 / 弹入 |
| 轴上的**推进位置**（第 N 步 → 第 N+1 步，V6） | 旋转、自动巡航 |
| 条的**长度**（概率重排，V5） | 缩放弹跳、spring |
| 点的**归堆**（参数改变导致重新分配，V9） | 粒子汇聚 / 飘散 |
| 明度**深浅**（把握度变化，V3） | 辉光呼吸、颜色脉冲 |
| 数字**直接变**（不翻牌） | 数字翻牌 / 滚动 |

### 与既有 token 的关系

G1 不新增时长。所有合法动效仍必须落进 `m-pointer` 150ms / `m-expand` 250ms / `m-sampling` 1.2s 循环三档（`design-system.md` §7）。G1 只是在「值合规」之前多加一道「凭什么动」。

**推论（清债依据）**：`index.css` 现存 20 组 keyframes 中，凡答不出 G1 第 1 问的一律删除。按此判据，`birth-scene-converge` / `birth-scene-scatter` / `scene-storm` / `fission-in` / `chamber-drop` / `chamber-bar-pulse` / `team-flow-dot` 均属**动外观**而非**动状态**，应删或重构为 V4/V5/V9 的形态。保留 `spin`（仅细环 spinner 的过渡期用途）、`token-in`、`pop-in`、`drawer-in`、`mask-in`（浮层进出，属 `m-expand`）。

## 3 · 逐条规格

### V1 · 概率 = Dot Plot（频率框架）

**为什么不是百分比裸数字**：公众对概率百分比存在**系统性误解**，且这不是教育问题而是认知框架问题。降雨概率的研究显示，「70% 降雨概率」被普遍误读为「70% 的区域下雨」或「70% 的时间下雨」（A-2）。产品内已记录同类现象：「普通用户看 `0.62/0.18/0.07` 的反应是『所以呢？』」。

**为什么不是饼图**：饼图要求用户比较角度与面积，精度低于位置与长度编码；且饼图暗示「一个整体被分割」，而 next-token 分布是**一次抽样在候选间的竞争**，语义不符。

**为什么是点阵**：频率框架（frequency framing）优于概率框架，有实验支持。「100 次里大约 40 次」不需要解释，因为它就是人脑处理可能性的原生格式。CHI 2018 的对照实验（公交到站决策）显示 quantile dotplot **显著改善实际决策质量**，优于连续密度曲线与误差棒（A-1）。

**规格**

| 项 | 值 | 理由 |
|---|---|---|
| 点数 | **100** | 频率框架的分母必须是 100，不是 20 或 64 |
| 网格 | **10 × 10** | 必须是易数的方阵。**禁止 7×14、5×20 等不易数的形状**——icon array 的排列方式会系统性扭曲比例判断（A-6） |
| 点形 | 圆点，直径 4px，间距 2px（总 60×60px） | 点必须可数；小于 3px 即不可数 |
| 着色 | 胜出候选 = `measure`；次位候选 = `measure` 明度 -2 档；**其余候选合计 = `ink-3`** | 单色明度阶，禁多色（承 `design-system.md` §1.3）|
| 分组 | 同候选的点**必须连续占据整行/整块**，不得散布 | 散布的点无法被数 |
| 尾部 | **「其余候选合计」必须在同一阵中占据其真实点数** | 承宪法：展示 top-2 必须同时给其余合计，禁造二选一错觉 |
| 舍入 | 点数 = `round(p × 100)`，总和强制为 100（差额补给最大项） | 不允许出现 99 或 101 点 |
| 数字副标 | 点阵下方一行等宽 `tabular-nums` 百分比 + 口径 | **见下方「与宪法的调和」** |

**与宪法的调和（重要）**

有一种主张是「以后产品里不要出现 `63%`，只出现点阵」。本篇**不采纳其字面版本**，理由是它与宪法冲突且会伤害 U2/U3 用户：

- 宪法明文要求「数字必带单位 + 口径 + 来源」「任何陈述句必须可点开到原始数据」「分数五证齐全」。删掉数字会直接违宪。
- U2（从业者）与 U3（研究者）需要的正是精确读数与可引用口径。删数字等于把产品降级成科普玩具。

**采纳的版本**：**点阵是主形式，数字是副标。** 顺序恒为「先看见形状，再读到数字」——点阵在上（视觉主体），等宽百分比在下（`micro` 档 `ink-2`）。这同时满足两条已有记录：「U1 不看数字看形状」与「数字给 U2，条形给 U1」。

**三档降级（性能与密度）**

229 步 × 100 点 = 22,900 个 DOM 节点，不可接受。按视图层级分档：

| 层级 | 形式 | 点数 |
|---|---|---|
| 正文行内（token 旁） | **不用点阵**，用 V3 的明度着色 | 0 |
| 卡内（当前时刻卡 / 证据卡） | 点阵 | 100 |
| 检查器（Inspector / 显微镜） | 点阵 + quantile dotplot（连续量） | 100 |

行内一律不画点阵——这既是性能要求，也是 P28（一屏一问）要求：正文的任务是读答案，不是读概率。

**实现**：单个 `ProbDotPlot` 组件，全站唯一实现，替换现有 4 套概率条中「表达单步分布」的用途。100 点用 CSS Grid 渲染（100 个 `<span>` 可接受）；若同屏 >3 个实例，改 canvas。

**验收**：给一个不懂 AI 的人看点阵 5 秒，问「这个词有多大可能被选中」，回答应是「一百次里大概四十次」而不是「40%」或「不知道」。

### V2 · 多次采样 = HOPs Reel

**为什么它对 LLM 特别成立**：HOPs（Hypothetical Outcome Plots）不画分布，而是**反复播放一个个具体的抽样结果**，让观察者自己形成频率感。实验显示 HOPs 在若干任务上优于误差棒与小提琴图，且**未受训练的观察者**也能使用（A-3）。

而 LLM 采样**本来就是**每次抽一个。连播同一 prompt 的 N 次真实续写，是对「为什么它每次答得不一样」最直接的回答——这不是隐喻，这就是机制本身。任何静态分布图都做不到这一点，因为静态图展示的是「分布」，而用户的困惑是「为什么两次不一样」。

**规格**

| 项 | 值 |
|---|---|
| 节奏 | 400ms / 条，条间无过渡动画（直切） |
| 条数 | **有界，5 条**，播完自动静止在最后一条 |
| 复播 | `Replay` 按钮（Secondary），点击再播 5 条 |
| 收束文案 | 播完后常驻一行：同一个模型 · 同一句问题 · N 次不同的结果 |
| 每条内容 | **必须是真实录制的样本**，标注其 seed |
| reduced-motion | 降级为**静态列表**，5 条同时呈现 + 一行说明 |

**三个硬约束（不满足则不能上线）**

1. **禁无限循环。** 宪法：唯一合法的循环动画是「测量中」指示，同屏 ≤1 处。HOPs Reel 是有界播放 + 用户主动复播，不是环境动画。无限循环版本违宪。
2. **每条必须是真实样本。** 这是 P1 Evidence First 的直接推论。**不允许手写 5 句励志话冒充 5 次采样结果**——那是伪造数据，是本产品的存在理由的反面。
3. **数据前置条件（当前不满足，但不阻塞实现）。** HOPs 需要 **N 条同 prompt、不同 seed 的真实 trace**。项目当前只有 `src/assets/demo.aitrace.json` **一条**。

**UI 不被数据阻塞（本篇的一般原则）**

数据没到，不等于组件不能做。**UI 与数据并行推进**——组件按完整形态实现，数据未达时呈现 V10 诚实空态，数据入库后直接接上，无需返工。这不是妥协，这正是 P9（诚实缺席）的原意：空态是合法终态，只要它交代了缺什么、为什么缺、怎么获得。

V2 的空态规格：

| 项 | 内容 |
|---|---|
| 缺什么 | 本视图需要同一问题的多次录制 |
| 为什么缺 | 当前档案中该问题只有 1 次记录 |
| 怎么获得 | Secondary 按钮「换一个 seed 再跑一次」→ 跑完自动入列 |
| 已有样本 | 已录制 1 / 5，并**把这 1 条真实样本正常显示出来**（不留空壳） |
| 禁止 | 用占位文字冒充第 2–5 条；灰化的假样本；无限转圈 |

这条空态本身就有产品价值：它把「你还差 4 次录制」变成一个**明确的、可执行的下一步**，用户每跑一次都在填格子。比先做数据、UI 干等着更好。

**推广为规则**：本篇任何语法元素，只要形式已定，**都可以在数据到位前实现**，条件是空态必须满足 V10 三要素、且已有的真实样本必须照常显示。倒过来则不允许——**不得为了让 UI 看起来完整而伪造数据**（附录 B 的候选池是"形式未定"，与"数据未到"是两回事）。

**与现有首屏定稿的冲突（需拍板，不由本篇裁决）**

`docs/首屏文案稿.md` 已定稿一套首屏叙事：谜题句「为什么同一句问题，AI 每次回答都不一样？」→ 谜底句「因为这个答案，曾经差点变成另一个答案。」→ 证据切片（步 68：`本身 20.08% / 这个词 20.08% / 其余合计 59.84%`）→ 按钮「亲眼看这一刻 →」，且首屏动效预算已定为 **≤1 处**（两根等长条 600ms 生长）。

HOPs Reel 若上首屏 Hero，将**替换**这套叙事的证据环节，并占用全部动效预算。两者的差别是叙事策略层面的：

| | 现有定稿 | HOPs Hero |
|---|---|---|
| 回答路径 | 提问 → 给一个决定性瞬间的证据 | 提问 → 直接展示现象本身 |
| 认知负荷 | 需要理解「概率几乎相等」 | 只需看见「五次不一样」 |
| 数据成本 | 1 条 trace（已有） | ≥5 条 trace（需录制） |
| 风险 | 「所以呢？」——已被记录发生过 | 用户可能读成「AI 不稳定/坏了」，需靠收束文案纠偏 |

**本篇的建议**（非裁决）：两者不是互斥的，HOPs 回答「是什么现象」，切片回答「为什么会有这个现象」，**顺序应为 HOPs 先、切片后**——先让人看见现象，再解释机制。这符合 `01-Cognitive-DNA.md` 的认知时序与 P27（Evidence → Pattern → Meaning → Explanation，禁倒序）。但这构成对已定稿首屏的改动，须走定稿评审。

### V3 · 不确定性 = 单色明度阶 + 点阵离散度

**明确否决「Entropy Glow」。** 有一种提案是「颜色越散越不确定，用 Entropy Glow」。本篇否决 Glow 形式，理由是三重冲突，且有替代方案：

1. `design-system.md` 全局禁令第一条：**不要 Glow（辉光/发光描边/彩色阴影）**。
2. `02-Visual-DNA.md` 轴三判据：「删掉界面上所有『发光』的像素，信息与美感是否毫发无损？凡删掉会变丑的辉光，都是装饰。」
3. `ui-audit.md` 已把现存 4 处彩色发光阴影 + `anomaly-glow` keyframes 列为**阻断级违禁品**。新增 Glow 等于把刚要还的债重新借一遍。

**替代方案（更准确且免费）**：**点阵的铺开程度本身就是熵的最佳表达。**

- 低熵：100 个点几乎全挤在一堆 → 视觉上「聚」
- 高熵：100 个点摊在很多堆里 → 视觉上「散」

这不是隐喻，是**熵的定义的直接图形化**。它不需要新增任何颜色或效果，与 V1 共用同一个组件，且天然满足「删掉它会少理解什么」的检验——删掉就看不出分布集中还是分散。

**规格**

| 用途 | 形式 |
|---|---|
| 正文 token 着色 | `measure` 单色 **5 档明度阶**，深 = 把握度高。禁多色梯度 |
| 分布集中度 | V1 点阵的堆数与最大堆占比（无需额外元素） |
| 高熵标记 | `caution` 色**点式下划线**（静态，现有 `.token-anomaly` 做法正确，保留） |
| 熵读数 | 等宽 2 位小数 nats + 口径行 |

**禁止**：Glow、抖动/噪声表达不确定性（NYT Election Needle 是公认反面案例——抖动激活情绪而非理解，A-5）、面积锥（hurricane cone 被广泛误读为「量级」而非「可能范围」，A-5）。

### V4 · 计算状态 = 流动虚线 → 实线

**偷自 CNN Explainer**：动画进行中边为**流动虚线**，动画完成后**转为实线**（A-7）。用线型而非额外元素表达计算状态，零额外像素成本。

**为什么它取代 Spinner**：Spinner 与「思考中…」的信息量是**零**——它只说「在忙」，不说「忙到哪了」。流动虚线同时表达三件事：**哪一段在算、哪些已完成、整条链的结构**。这是状态可视化，不是等待动画。

**规格**

| 状态 | 形式 |
|---|---|
| 未开始 | 1px `line` 实线，`ink-3` |
| **进行中** | 1.5px `measure` 虚线，dash `4 4`，`stroke-dashoffset` 循环 1.2s linear |
| **已完成** | 1.5px `measure` 实线 |
| 失败 | 1.5px `alert` 实线 + 断口 |

**合法性**：这是一个循环动画。宪法允许的唯一循环动画是「测量中」指示（`m-sampling`，1.2s，同屏 ≤1 处）。流动虚线**就是**测量中指示的图形形态，因此合法，且必须复用 `m-sampling` 的 1.2s 时长。**同屏只允许一条线段处于「进行中」态。**

**替换清单**（现存组件按此改造）

| 现状 | 改为 |
|---|---|
| `.spinner`（细环旋转） | 流动虚线（管道场景）；非管道场景保留细进度条 |
| `.breath-dot`（静态点） | 删除，由流动虚线承担 |
| `.typing-cursor` | 保留（文字流本身即活动反馈） |
| 「深度思考中…」 | **必须改**为「推理段 · 生成中 N 秒」（已登记为违宪债务 V-1）|
| 「AI 正在思考…」类文案 | 「正在采样 · 第 N 步」 |
| `.demo-resume-pulse`、`anomaly-glow` 等装饰 keyframes | 删除 |

`reduced-motion`：虚线静止（保留虚线形态，仅停止 offset 动画）——**形态本身仍在传达状态**，这是它优于 spinner 的又一处：降级后不丢信息。

### V5 · Token 竞争 = Candidate Ladder

**规格**：水平条形，全站唯一实现。收编现有 4 套独立实现（InstrumentCluster / SamplingInspector / ActivityLog / BirthCard）。

| 项 | 值 |
|---|---|
| 方向 | 水平，向右，左端对齐 |
| 排序 | 概率降序，胜出者在最上 |
| 条高 / 行距 | 8px / 4px |
| 着色 | 胜出 `measure`；落选 `measure` 明度 -2；**尾部合计 `ink-3`** |
| 标签 | 左侧 token 原文（等宽），右侧概率（等宽 `tabular-nums` 右对齐） |
| **尾部常驻** | **「其余 N 个候选合计 X%」必须常驻末行**，不得折叠、不得省略 |
| 选中 | `measure-wash` 弱底 + 1px `measure` 边框（承 §23 全站唯一选中语言）|
| 丝印 | 左上角等宽小字：数据来源 + 截断口径（Top-8 · 全量 softmax 后截断） |

**尾部常驻是宪法要求**：切片不得省略会改变结论的上下文，展示 top-2 必须同时给其余合计，禁造二选一错觉。

**与 V1 的分工**：Ladder 回答「有哪些候选、各自多少」（比大小任务）；Dot Plot 回答「有多大可能」（概率理解任务）。同一份数据，两种任务，**两者可同屏共存**（Ladder 在上给结构，Dot Plot 在下给频率感），但**不得互相替代**。

### V6 · 时间 = Timeline（宽度 = 真实耗时）

沿用 `Observe页融合重构方案-v2.md` 已定稿的规格，本篇只补一条依据与一条禁令。

**依据**：Chrome DevTools Performance 面板的 waterfall 语法——**耗时成为宽度**。这让「哪一步慢」变成前注意知觉判断（一眼看出哪段最长），不需要读数字比较。

**禁令**：**禁止流程图贴纸。** 已记录的反面案例：「8 个带对勾的方块 + 箭头，折成 3 行……是流程图贴纸不是测量记录」。带对勾的等宽方块序列**不承载任何测量**——每个方块一样宽，等于宣称每步耗时相同，这是错的。

| 项 | 值 |
|---|---|
| 轴向 | 横向向右，全站无例外 |
| 段宽 | ∝ 真实耗时，**log 刻度**（否则慢步会淹没所有快步） |
| 高度 | 轴体 24px + 刻度行 16px |
| 事件标记 | ▲ 于刻度行，不在轴体内 |
| 单位 | 轴端标注量级（ms / s） |

### V7 · 因果 = Flow Graph（含未解释残差）

**用于**：Agent 交接、检索→规划→作答的归因链、（未来）attribution graph。

**偷自 Anthropic attribution graph 的一招（最重要）**：图里必须有 **error node / 未解释残差节点**——把「我们没解释掉的部分」显式画出来，并标注当前视图剪枝了多少（A-10）。

这一条与本产品的 P9（诚实缺席）是同一个精神在图论上的表达。一张只画「解释得通的路径」的因果图，是在暗示「这就是全部原因」，而这通常是假的。

| 项 | 值 |
|---|---|
| 结构 | DAG，从左（输入）到右（输出） |
| 边 | 1.5px，粗细 ∝ 归因强度；**仅当有真实归因数据**，否则等粗 |
| 节点 | Card 规格（`surface` + 1px `line` + `r-md`） |
| **残差节点** | 必备。样式：1px 虚线 `line-strong` 边框 + `ink-3` 文字 + 「未解释：X%」 |
| 剪枝披露 | 图下方一行 `micro`：本图省略了 N 个弱归因节点（阈值 X） |
| 交接原因 | 边上必须携带 reason；**缺失时写「交接原因未记录」**，不留空、不编造 |

**禁止**：装饰性连线（不承载归因的连线一律删除）、无向连线（因果必须有向）、几何飞行动画（Artifact 已位于连接线上，语义已表达）。

### V8 · 空间结构 / 规模 = 3D（唯一的感受型语法）

**这是全表唯一标记为「感受」的元素**，因此受 §1 的感受型预算约束：同屏 ≤1 处、不承载必读信息、删掉不影响任务完成。

**3D 的唯一合法理由（最高判据，措辞刻意收紧）**：

> **3D 只能用于原始数据本身具有三个以上自由度的对象。否则不用。**

用「**自由度**」而不是「维度」，是因为「维度」可以被诡辩——任何数据都能被说成「有概率维、有时间维、有排名维」。自由度问的是**数据本身有几个可以独立变化的量**，这个数是客观的、可以数出来的，无法靠修辞增加。

Token 概率就是一列数：给定一步，`p` 是唯一自由变量，排名是 `p` 的函数，不是独立自由度。**自由度 = 1。** 所以它无论怎么包装都不该上 3D。

| 对象 | 自由度 | 3D 是否成立 |
|---|---|---|
| Embedding 空间 | 高维（768+），降维后第三主成分仍携带信息 | ✅ 成立（A-12） |
| Layer × Head × Position | 三个正交轴同时在场 | ✅ 成立（A-11） |
| Residual stream 逐层演化 | 层深 × 序列 × 维度 | ✅ 成立 |
| 模型规模对比 | 需要**体验**数量级，而非读数 | ✅ 成立（A-11） |
| **单步 token 概率分布** | **一维（就是一列数）** | ❌ **不成立** |
| **Top-k 候选竞争** | **一维排序** | ❌ **不成立** |

**补充判据**：即使自由度 ≥3，若任务是「读具体值 / 比大小」，仍一律 2D。3D 只服务「感受规模量级」与「识别本质三维的拓扑结构」这两类任务。**自由度是必要条件，任务类型是充分条件，两者都要满足。**

Activation Grid 是很好的边界案例：它概念上是三维立方体（x × y × channel），但 Distill 把它**拍扁成 2D 网格 + 面积编码**，因为读者的任务是「读出哪个位置激活了什么」——**查值任务的位置+面积编码精度远高于 3D 透视**（A-13）。

#### 准入四门（全过才能上 3D）

1. **自由度门**：数出原始数据的独立自由度，**必须 ≥3**，并写出「2D 会丢失哪一个自由度」。排名、次序、名次这类由主变量派生的量不计入自由度。
2. **任务门**：认知任务是「感受」而非「读值」（G0 已声明）。
3. **降级门**：有完整的 2D 降级路径，且降级后**任务仍可完成**。移动端与软件渲染环境**默认走 2D**。
4. **证据门**：3D 里每一个可见元素都能答出「它由 trace 哪个字段驱动、当前值多少」（承 P25）。

#### 补偿四件套（上了 3D 就必须全上）

3D 的深度线索天然不足，Embedding Projector 的做法是叠加**三重冗余深度线索**（A-12）。本篇要求四件，缺一即为不合格实现：

1. **近大远小**：点/块尺寸随相机距离变化。
2. **雾化**：远处元素淡出（不是消失）。
3. **初始缓转**：入场时一次缓慢自转，制造运动视差**建立空间感后停止**——注意：这是一次性入场动效（≤600ms 预算不适用于建立空间感的必要旋转，但**必须自动停止，禁止自动巡航**，承宪法红线）。
4. **Billboard 文字**：所有文字标签永远正对相机。3D 里的透视文字不可读，这是硬约束。

#### 「格子可数」（bbycroft 的可偷之招）

不要用抽象矩形代表向量。**把维度画成能一个个数出来的 cell，且 cell 数量真实**（必要时 LOD 降级，但降级须标注「按 1:N 抽样显示」）。这是「看懂规模」的唯一手段——用户第一次能亲眼看到 768 维有多宽（A-11）。

#### 现有 3D 资产逐一裁决

| 资产 | 裁决 | 理由 |
|---|---|---|
| `OceanView`（概率海洋） | **改造或降级** | 表达的是 token 概率，**自由度 = 1，自由度门不过**。已记录批评：「现在的词海视觉＝从仓库里挑词，暗示数据库/字典检索——这是对 LLM 的误导」。软件渲染下的诚实停用做法**正确，保留** |
| `BirthScene` 粒子层 | **删表现，留数据** | 场面型动画违反指针语法；数据重构进 V1/V5 |
| `InstrumentCluster` 柱林 | **降为 2D Ladder** | 「柱子太单薄」的根因不是柱子不够粗，是它用三个自由度表达自由度为 1 的数据；三个已记录问题（标签重叠、词太小、词沉到 Z 轴下）全是这个错误的必然代价 |
| **新增：Embedding / Layer 空间** | **这里才是 3D 该去的地方** | 自由度门、任务门全过。但需要 hidden state 导出（当前 runtime 未导出）——按 §V2 的「UI 不被数据阻塞」原则，**组件可先实现 + 诚实空态**，但**绝不伪造张量** |

**结论**：产品当前的 3D **全部用错了地方**——用在一维数据上；而**真正需要 3D 的地方（embedding / layer 空间）因为缺数据而空着**。这不是「3D 太少」，是「3D 装错了轴」。用户感觉「三维效果太少」，真实原因是现有 3D 没有承载任何 2D 承载不了的东西，所以看完没有获得感——不是数量不足，是**每一处都没兑现 3D 的承诺**。

### V9 · 参数变化 = Morph

**用于**：temperature / top-k / top-p 滑杆。

**规格**：同一个图形**连续变形**，不切换画面、不并排前后对比。

| 参数 | Morph 的具体形态 |
|---|---|
| temperature ↓ | V1 点阵的点**向最大堆迁移**（低温 = 全挤一堆） |
| temperature ↑ | 点**向各堆摊开** |
| top-k / top-p | 不入选的堆**整体灰化并移出**（不是消失——保留其存在，标注被截断） |

**为什么必须是 Morph**：参数的作用是「重新分配」，Morph 直接图形化这个动作；并排前后图要求用户自己做差分，认知成本高且容易读错。

**时长**：跟随滑杆实时（`m-pointer` 150ms）。不做入场动画。

**关键约束**：Morph 的每一帧**必须是真实计算结果**（对当前 logits 重新 softmax），不是插值动画。伪造的中间帧违反 P1。

## 4 · 数字呈现制度：频率优先，精度不丢

| 场景 | 主形式 | 副标 |
|---|---|---|
| 给 U1 讲一个概率 | 点阵（V1） | 等宽百分比 + 口径 |
| 给 U2 读多个概率 | Ladder（V5）等宽右对齐 | 尾部合计常驻 |
| 给 U3 引用 | 表格 + 原始 JSON 下钻 | 五证齐全 |

**转写规则**：界面上出现的**每一个概率**都必须能被读成频率句。文案层面优先写「一百次里大约 40 次」，读数层面保留 `40.2%`。

**仍必须给百分比数字的场合**（不得只给点阵）：任何需要被引用、对比、复现的读数；任何进入分享卡 / 导出 / 成绩单的数字。承宪法：数字必带单位 + 口径 + 来源，等宽 + `tabular-nums` + 右对齐 + 单位常驻，无例外。

## 5 · 文案：设备不是用户的错

用户明确反馈：「很多提示词比如底配电脑这种话术会让人很不舒服」。这条反馈是对的，且**属于本篇职权**——因为空态与失败态是 V10 的一部分，而文案是它的载体。

**病灶**：把「测不出来」表述成**对用户设备的评价**。用户来观察 AI，却被告知自己的机器不行——这是失礼，且它违反 `02-Visual-DNA.md` 轴一（可信不是冰冷）。

**改写规则（三条）**

1. **说机制与阈值，不评价设备等级。** 禁用词：低配、底配、设备较慢、配置较低、需要较好的显卡、性能不足。
2. **给可执行的下一步**，而不是给一个判决。空态是合法终态，但必须有唯一下一步。
3. **主语是限制本身，不是用户。** 「这台机器不行」→「这项测量需要 X，当前环境没有 X」。

**取证与逐条改写建议**（`src/` 实测）

| 位置 | 现状 | 建议改为 |
|---|---|---|
| `lib/models.ts:92` | 需要较好的显卡 | 需要约 N GB 显存（未达时可运行，速度下降） |
| `lib/models.ts:147` | 需要高性能显卡 | 需要约 N GB 显存 |
| `lib/models.ts:33` | 档位注释 `1=无独显/低配` | `1=无独立显卡` |
| `lib/device.ts:14` | `1=无 GPU/低配` | `1=无 GPU` |
| `worker.ts:414` | 视显卡性能可能需要数十秒 | 正在编译着色器 · 首次运行需 10–60 秒，之后有缓存 |
| `worker.ts:341` | 该设备上的推理数值异常……建议更新显卡驱动 | 保留机制陈述（fp16 兼容），删除「该设备」的评价口径，改为「当前 WebGPU 后端的 fp16 路径返回 NaN」 |
| `ObservePage.tsx:599/857` | 注释 `多为低配设备 WASM 内存不足` | `多为浏览器内存不足` |
| `OceanView.tsx:591` | 当前设备使用软件渲染，三维视图不可用 | **保留**——这是中性机制陈述，合格 |
| `worker.ts:165` | 网络问题，不是设备性能问题 | **保留**——主动排除误解，做法正确 |

**顺带**：`批次5-验收记录` 已登记「模型描述营销级形容词」待拍板（如「能力最强」「回答质量最高」）。此项与本节同源——都是文案在替用户下判断。建议一并处理：模型描述只写**可验证的规格与实测口径**，不写比较级形容词。

## 6 · 反面清单（一票否决）

1. 概率画成饼图、雷达图、词云、旋转球、发光体。
2. 用 Glow / 抖动 / 面积锥表达不确定性。
3. 一维数据用 3D 表达。
4. 3D 缺补偿四件套中的任何一件（尤其：透视文字、自动巡航）。
5. Spinner 或「思考中…」承担计算状态表达。
6. HOPs 的帧是手写的、不是真实录制的样本。
7. 概率切片省略「其余候选合计」。
8. 因果图缺未解释残差节点 / 不披露剪枝。
9. 无真实数据的 attention 可视化。
10. 感受型视觉承载必读信息，或同屏 >1 处。
11. 文案评价用户设备等级。
12. 同一个量在同屏出现两种不同图形（承一致性高于新鲜）。

## 8 · 验收

## 附录 B · 尚未采纳的候选（候选池）

按 §0.2 的准入条件，以下想法有价值但**证据或数据尚不足**，登记在此，不进产品：

| 候选 | 缺什么 |
|---|---|
| Plinko / Galton board（落球建立频率感） | 证据显示适合「教会一次」，日常界面用静态点阵更稳（A-4）。可考虑用于一次性引导，不用于常驻界面 |
| logit lens 热图（格子里印 top-1 token 文字，看想法逐层成形） | 需要逐层 hidden state 导出。**当前 runtime 未导出**。这是本产品最值得做的空白位——现有工具全是 Python/matplotlib，没有好的纯前端交互版本 |
| BertViz 式 model view（层 × head 缩略图墙做导航） | 需要 attention 数据 |
| AttentionViz 式「距离≈注意力」散点 | 需要 attention 数据 |
| GAN Lab 式「扭曲网格」表达分布被变换 | 形式很好，但本产品暂无对应的「函数变换」对象 |
| 预计算 trace + JSON 回放讲大模型（A-14） | 是绕过浏览器算力限制讲大模型的正解，但改变产品的「本机实测」定位，须拍板 |
