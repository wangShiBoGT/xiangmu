# AI Observatory E5 · Volume I · Product Constitution（产品宪法）

> 本卷不含任何需求、页面、技术方案。它回答的唯一问题是：这个产品为什么存在，
> 以及它永远不做什么。所有后续卷册、所有代码，都从属于本卷。
> 修宪需要明确理由并记录在案；违宪的功能无论多好看都不上线。

## 第一章 · Philosophy（产品哲学）

### 1.1 为什么这个产品存在

人类历史上每一次「看见不可见之物」都催生了一门科学：显微镜之于微生物学，
望远镜之于天文学，示波器之于电子学。AI 是人类造出的第一个自己也无法直接看见其
运作的造物——数十亿人每天与它对话，却没有一件日常仪器让普通人**亲眼看到**
它每个字是怎么来的。

AI Observatory 存在的理由只有一句：

> **人类第一次观察 AI，本应该是什么体验——我们把它造出来。**

### 1.2 为什么不是聊天

聊天软件的度量是「答案有多好」；仪器的度量是「观察有多真」。
聊天把生成过程藏起来，因为过程对「得到答案」是噪音；
我们把过程亮出来，因为过程对「理解 AI」是全部。
同一个模型、同一次生成，聊天框和观察仪展示的是两个世界——我们选后者，
且永远不为了「答案更好用」牺牲「观察更真实」。

### 1.3 为什么不是 Playground

Playground 服务开发者调参，前提是用户已经懂 temperature、top-p 是什么。
它是给会开车的人调发动机的工位。我们的用户第一次打开引擎盖——
仪器必须先制造「想看」的欲望，再交出「能调」的旋钮。
Playground 是参数优先，Observatory 是好奇心优先。

### 1.4 为什么不是 Dashboard

Dashboard 的隐含承诺是「你要监控的东西都在这里」——它服务已知问题。
观察仪服务未知问题：用户来之前并不知道自己要看什么，
是仪器引导他发现值得看的东西（犹豫点、分岔、衰减）。
Dashboard 陈列指标；Observatory 制造发现。

### 1.5 为什么不是 Demo

Demo 演示「它能做到」，播完即结束；仪器供人「反复使用」，每次观察都可能不同。
判据：一个功能如果只能看一次、第二次没有新信息，它是 Demo，不配进入本产品。
我们的每个视图都必须回答：用户第二次来这里，会看到什么新东西？

### 1.6 一句话定位

> 别人做 AI Story（讲 AI 的故事），我们做 AI Evidence（出示 AI 的证据）。
> 观察 AI，而不是观察答案。

### 1.7 使命句

> **理解 AI，不应该依赖信任，而应该依赖观察。**
> **Don't trust AI. Observe AI.**

实现方式副句：我们不是把 AI 的数据画出来，我们把 AI 的思考翻译成人类能够理解的语言。
产品定位：AI Understanding / Literacy Interface——The Language for Seeing AI Think。
北极星指标：第一次接触 AI 的人，20 分钟建立正确心智模型（不是数据库、不是搜索、不是提前写好的）。

## 第二章 · Design Principles（设计原则，31 条，按三层级归位）

> 原有四条（P1–P4）升格为「基本法」，其余为「通则」。
> 自 P27 起，全部原则收敛为三层级：**价值层（Why）**：P1、P9、P25、P26、使命句；
> **认知层（How people understand）**：P27、P28、P29；**交互层（How the interface behaves）**：P30、P31 及既有交互通则。
> 此后新增原则必须归入三层级之一，归不进就不新增——原则随能力稳定，不随功能膨胀。
> 每条附一句可操作检验——不能检验的原则是口号，不收录。

### 基本法（P1–P4，不可修订）

**P1 · Evidence First（证据优先）**
所有结论必须可回溯到真实 Trace。
检验：界面上任何陈述句都能点击展开到产生它的原始数据与来源路径。

**P2 · Show, Don't Tell（展示而非断言）**
展示数据，不替用户下结论。
检验：删掉界面上任意一句解释文字，证据本身仍能支撑用户得出相同结论。

**P3 · Curiosity Before Explanation（好奇先于解释）**
先制造问题，再解释原理。
检验：每个入口页只提出问题；名词解释永远出现在用户已经看到现象之后。

**P4 · Every Click Earns the Next Click（每次点击赚下一次点击）**
每次点击都要兑现上一次承诺，并制造下一次好奇。
检验：每个按钮的文案写得出「承诺什么/下一屏用什么兑现」两栏。

### 通则（P5–P24）

**P5 · Scientific Instrument（科学仪器）**
一切设计语言来自实验室、观测站、控制中心，不来自营销页、电商、社交媒体。
检验：任一界面截图放进「科研软件」和「营销网站」两组里，人类分类者应把它放进前者。

**P6 · No Decoration（无装饰）**
所有动画与视觉效果必须承载对 AI 的解释，不为炫技存在。
检验：对每个动效问「它让用户理解了什么」——答不出即删除。

**P7 · No Fake Intelligence（不伪造智能）**
不拟人、不虚构内部状态。没有真实数据支撑的「AI 在想什么」类展示一律禁止。
检验：界面上每个关于模型内部的可视元素都对应一个真实张量/概率/时间测量。

**P8 · Replayable Truth（可重放的真实）**
任何观察结果都可以被精确复现——seed、参数、trace 齐全，重放即重现。
检验：任一实验档案在另一台机器上导入后，逐 token 与原记录一致。

**P9 · Honest Absence（诚实缺席）**
测不到就不显示，不估算、不外推、不放占位假数据。空态是合法终态。
检验：全站不存在任何「约」「估计」「大概」修饰的核心数字。

**P10 · Layered Disclosure（分层披露）**
结论在最上层，证据在第二层，原始数据在最深层；每层自愿下潜，不强迫。
检验：普通用户止步第一层仍获得完整叙事；研究者能一路下潜到原始 JSON。

**P11 · One Primary Action（每屏唯一主动作）**
一屏只有一个高对比主动作；其余一律降级为次级样式。
检验：任意一屏视觉扫描 3 秒内能唯一指出「产品希望我点什么」。

**P12 · Instrument Never Lies About Itself（仪器不谎报自身）**
仪器自身的局限（采样截断、口径差异、量化损失）与观察结果同等显著地展示。
检验：每个测量视图都有一行「本测量不包含什么」。

**P13 · Anthropomorphism as Index Only（拟人词只作索引）**
「犹豫点」这类词可以作为位置的名字（引人进门），不可作为断言（AI 犹豫了）。
检验：拟人词出现处点开必是概率证据，且正文陈述句中不出现拟人谓语。

**P14 · Separate Provenance, Always（来源永远分离）**
不同来源的数据（官方引用/本机实测/行为统计）永不同表、永不同色、永带来源标。
检验：任意滚动位置截屏，画面内每个数字都能看出它属于哪个来源层。

**P15 · The User Concludes（用户下结论）**
产品陈列证据的排布可以有立场（引导注意），但结论性语句由用户产生。
检验：用户访谈中「原来 AI 是这样」这句话由用户说出，而不是页面写出。

**P16 · Waiting Is Teaching（等待即教学）**
不可避免的等待（模型加载、生成中）用真实教学内容填充，不用假进度条欺骗。
检验：所有等待态要么显示真实进度，要么显示真实示例数据，无一虚构。

**P17 · Every Number Has a Unit and a Method（数字必带单位与口径）**
任何数字旁边必须能看到单位与测量方法。
检验：全站不存在裸数字（无单位、无口径、无来源三缺一即违例）。

**P18 · Consistency Over Novelty（一致性高于新鲜感）**
同一语义永远用同一组件、同一图标、同一交互；新场景优先复用既有语言。
检验：新功能评审第一问是「现有语言能表达吗」，能则禁止新造。

**P19 · Mobile Reads, Desktop Operates（手机读，桌面做）**
移动端保证完整的「读」体验；复杂操作诚实引导到桌面，不硬塞阉割交互。
检验：手机上无横向溢出、无不可达按钮、无假装可用实则残缺的操作。

**P20 · Slow Is Smooth（慢即是稳）**
宁可少上一个功能，不上一个违宪的功能；宁可空态，不provisional 凑数。
检验：每个批次的「范围外」清单与「范围内」清单同等认真地维护。

**P21 · The Trace Is the Product（Trace 即产品）**
.aitrace 文件格式是产品的真正资产——界面会换代，格式向后兼容永不破坏。
检验：任何历史版本导出的 trace 文件在最新版本可完整回放。

**P22 · Local First, Private Always（本地优先，隐私恒定）**
推理在本机、数据在本机；任何「分享」都是用户显式的文件/链接交付，产品不上传。
检验：断网状态下核心观察功能完整可用；网络面板无遥测请求。

**P23 · Failure Is Data（失败也是数据）**
模型跑崩、复读、工具调用失败——如实展示，它们是关于 AI 的真实知识。
检验：退化结局与成功结局用同等的设计质量呈现，不隐藏不美化。

**P24 · Five-Year Test（五年检验）**
每个设计决策问一句：模型换了三代之后，这个决策还成立吗？
检验：决策文档里「依赖当前模型特性」的条目单独标注，并写明失效条件。

**P25 · Every Pixel Has Evidence（每一个像素，都来自真实推理）**
P1/P6/P7 在视觉层的升级归零点：页面上不存在任何装饰性动画，所有视觉变化都由模型真实运行数据驱动。
背景在流——是真实熵；粒子——是真实候选；颜色变化——是真实概率；光带——是真实 Trace。
别人可以复制效果，复制不了数据来源；这是风格之上的产品哲学。
配套节奏约束（导演系统）：大场面只留给真实犹豫点，一直爆就是没有爆。
检验：任意指着一处正在变化的像素，都能回答「它由 trace 的哪个字段驱动、当前值是多少」；回答不出就删掉。

**P26 · Meaning over Data（先看到意义，再看到数据）**
P25 的另一半：证据必须翻译成意义。可视化对象是 Decision（这一步为什么这么写），不是孤立变量；
用户任何时候都不应该只看到「数据」，而应该直接看到「意义」——人话先行，指标下潜。
检验（四问）：每一个视觉元素必须能回答 ① 这是什么 ② 为什么会出现 ③ 它说明 AI 正在发生什么
④ 用户看完这一眼获得了什么新的理解；答不全 = 装饰，删除。
（设计稿住址：`docs/决策优先-AI思维可视化-重构设计稿.md`）

**P27 · Cognitive First（认知优先）**〔认知层〕
界面优先呈现可观察的证据，再帮助用户形成理解。呈现链固定为
Evidence → Pattern → Meaning → Explanation（可选），禁止倒序。
反对的是「抢在证据前面下结论」，不是反对解释：温度/seed/softmax 这类用户不可能
自行发现的机制仍然解释，但永远后置、下潜。
检验（五问 = P26 四问 + 第五问）：**不写一句解释，用户自己能不能看懂？**

**P28 · One Screen, One Question（一屏只回答一个问题）**〔认知层〕
任何一屏在任何时刻只回答一个问题；其余全部信息都是这个答案的支撑，默认下潜。
检验：评审时指着屏幕问「这一屏到底回答哪个问题」，答不出或多于一个 = 重新分层。
（判例：2026-07-25 创始人截图——生成中一屏同时在场七类专业面板，永久反面案例。）

**P29 · Pattern Before Numbers（先模式，后数字）**〔认知层〕
用户先看到形状、对比、变化，再看到概率、熵、耗时等具体数值；大脑识别模式，不阅读数字。
检验：任一数据呈现处遮住数字，用户仍能从形状得出同一判断；数字只出现在 tooltip/下潜层。

**P30 · One Visual Grammar（统一视觉语法）**〔交互层〕
全站所有动画与交互只能属于 Birth / Branch / Collapse / Flow 四种语法之一。
检验：任一动效能填出「语法归属 + 驱动字段 + 认知收益」三件套；归不进四语法 = 不上线。
（详表住址：`docs/design-language/02-visual-grammar.md`）

**P31 · Questions Drive Navigation（问题驱动导航）**〔交互层〕
页面导航、侧栏和入口围绕用户的问题组织，而不是围绕技术模块组织——
用户是在寻找答案，不是在浏览功能树。界面用「时刻 / Moment」，专业模式用「Decision Moment」，
代码与 Trace 保留 Decision。
检验：左栏每个入口都是一个用户读正文时自然产生的问题，点开即证据。
（详表住址：`docs/design-language/01-questions.md`）

## 第三章 · AI Language（语言宪章）

> 文案是产品最容易违宪的地方。本章是全站文案的白名单/黑名单，
> 所有新文案先过词表再上线。

### 3.1 允许的词（观察语言）

```text
Token / 候选 / 概率 / 分布 / 熵 / 采样 / 温度 / Seed
Trace / Replay / 分岔（Branch）/ 上下文 / 窗口
生成 / 输出 / 命中（规则）/ 衰减 / 延迟 / 吞吐
犹豫点*（仅作位置索引名，见 P13）
差点*（仅当可展开到概率差证据时）
```

### 3.2 禁止的词（拟人断言）

```text
AI 想 / AI 认为 / AI 决定 / AI 理解 / AI 意识到
AI 改变主意 / AI 偏好 / AI 记得 / AI 忘了
思考中… / 正在理解你的问题…
聪明 / 强大 / 有灵魂 / 像人一样
```

### 3.3 改写范式（每个禁词都有出路）

| 想说的 | 必须写成 |
|---|---|
| AI 犹豫了 | 这一步，前两个候选概率仅差 0.4% |
| AI 改变了主意 | 换一个 seed，这一步采样到了另一个候选 |
| AI 在思考 | 正在生成第 N 个 token（每 token 平均 X ms）|
| AI 理解了上下文 | 这 N 个 token 都在当前上下文窗口内 |
| AI 忘了前文 | 该内容已超出上下文窗口（第 N token 之前）|

### 3.4 执行机制

- 新文案评审附「词表检查」一栏；
- 拟人词若作为索引名使用，必须同时满足：① 点开即概率证据；② 不出现在陈述句谓语位。

## 第四章 · Brand Philosophy（品牌哲学）

### 4.1 品牌人格

可信、克制、理性、科学、探索、开放。
**不是**：炫酷、赛博朋克、「科技感」、营销感。

判词：我们的品牌参照物是天文台与实验室，不是发布会与预告片。
NASA 任务控制中心的屏幕没有一个像素是为了「看起来先进」——
每个像素都因为有人需要读它而存在。这就是我们的品牌上限。

### 4.2 双体系的世界观（既有决策，upgraded to constitution）

- **暗色 = 观察室**：观察 trace、三维、生成过程——天文台圆顶熄灯才能看星。
- **亮色 = 报告纸**：体检报告、成绩单、档案——科学结论印在纸上。
明暗不是主题切换，是**场所切换**；用户从暗到亮=从观测到结论，这个隐喻不许打破。

### 4.3 语气

短句。陈述。不感叹。不推销。允许幽默，但幽默必须来自事实本身
（「它差点用 20.08% 对 20.08% 掷了一枚完全均匀的硬币」是幽默，也是事实）。

## 第五章 · Product Grammar（产品语法）

一切页面、一切未来功能（Experiment / Benchmark / Agent / 社区）必须满足同一语法：

```text
Question（这一屏让用户带着什么问题）
   ↓
Evidence（用什么真实数据回应）
   ↓
Interaction（用户能亲手改变什么）
   ↓
Conclusion（用户自己得出什么，产品不代说）
   ↓
Replay / Next Question（如何复现，以及引出下一个问题）
```

- 缺 Question 的页面是 Dashboard（违宪 1.4）；
- 缺 Evidence 的页面是营销页（违宪 P1）;
- 缺 Interaction 的页面是 Demo（违宪 1.5）；
- 替用户写 Conclusion 的页面违宪 P15；
- 不可 Replay 的页面违宪 P8。

新功能立项模板即此五行——填不满五行的功能不立项。

## 第六章 · 修宪与执行

- 本卷条款分两级：基本法（第一章、P1–P4、第五章）不可修订，只可增补解释；
  通则（P5–P31、词表）可修订，修订须写明「原条款为何不再成立」并存档。
- 每个开发批次的验收记录必须包含「宪法自查」一节，逐条对照涉及原则。
- 冲突裁决顺序：基本法 > 通则 > 各卷规范 > 个人品味。
