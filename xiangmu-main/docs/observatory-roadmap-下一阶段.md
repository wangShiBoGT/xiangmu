# AI Observatory 路线图 · 下一阶段（讨论收敛稿）

> 收敛自 2026-07 的产品讨论：定位升维为 AI Observatory（观察 AI，而不是观察答案）。
> 本文只记录「方向已确认、但不在当前批次开发」的内容；当前批次见代码。
> 铁律不变：只展示 trace 真实记录的数据，没有记录就不展示，不伪造、不外推冒充实测。

## 北极星

**不回答「哪个 AI 最强」，帮用户回答「它为什么会这样表现，以及如何让它表现得更好」。**

用户身份不是消费者，而是实验者：
观察 → 干预 → 比较 → 沉淀 → 再观察。

## 已上线的对应能力（现状盘点）

| 主线 | 现状 |
|---|---|
| Observe 观察 | 实验台：逐 token 候选/概率/熵/耗时，Ocean 三维回放 |
| Experiment 实验 | 改选候选真实分叉、seed 复现、参数面板、规则标注 |
| Benchmark 评测 | 设备页「本机 AI 体检报告」：能力实测、速度基准、稳定性、上下文衰减曲线 |
| Discover 发现 | 发现页 Evidence Field：分叉/分布异常/规则事件/性能变化 |
| Archive 沉淀 | 实验档案 + Research Timeline + .aitrace 导入导出 |

## Benchmark 三层体系（渐进落地）

### 第一层：系统实测（已做，持续加深）
本机真实测量，全部诚实：TTFT、TPS、逐 token 耗时、稳定性（变异系数）、
上下文衰减率（首/末段速度比）、后端（WebGPU/WASM）。
后续可加：不同 prompt 长度下的首词延迟曲线、多次运行的历史留存与对比。

### 第二层：官方成绩引用（未做）
MMLU/HumanEval 等权威能力分**无法在浏览器可信复测**。
诚实做法：引用各模型官方公布成绩，逐条标注来源链接与「官方公布 · 非本机实测」，
与实测数据分区展示，绝不混入同一张评分表。

### 第三层：行为指标（原创，逐步定义）
基于我们真实记录的数据定义自己的可复现指标：
思考段长度占比、熵曲线形态（峰值/均值/突变次数）、规则命中率、
衰减率、候选集中度。每个指标必须给出计算公式与数据来源字段。

### Benchmark 规则包（生态方向）
现有规则系统（rules.ts，可导入导出校验）扩展为「可命名、可分享的规则包」：
个人定义 → 导出分享 → 他人导入复跑。远期形态是 Benchmark Store
（Official / Community / Personal 分区，可 Fork），需要后端，进二期后。

## 多模型组合（愿景，V2+）

方向成立：未来的强系统可能是多模型协作（规划/编码/视觉/检索/裁决各司其职），
Observatory 的观察对象从「单模型」升为「模型组合在什么任务下表现最好」。
依赖远程 API 接入与编排框架，且 trace 数据模型需扩展（多 run 关联、角色标注）。
**在 trace 里没有真实的 Agent/Memory/Tool 字段之前，UI 不得出现这些概念。**

## 明确不做（重申）

- 「Agent 城市 / Memory 海马体 / DNA 基因链 / Living AI」等无真实数据支撑的空间隐喻；
- 全球排行榜（需后端与防作弊，且违背「单机跑分、条件可比」原则）；
- 把引用成绩与实测成绩混排；
- 用估算/外推冒充实测（估算必须显式标注）。
