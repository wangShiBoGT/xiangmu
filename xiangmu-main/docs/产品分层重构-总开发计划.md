# 产品分层重构 · 总开发计划（V2 主线）

> **产品定义（创始人 2026-07-24 最终定调）：我们不是另一个 AI Chat，我们是第一个 AI Runtime Debugger。**
> 从 Observable（知道发生了什么）到 Debuggable（能停下来、检查、修改、继续运行、验证结果）。
> 对标的不是 ChatGPT，是 Chrome DevTools 的 Pause/Step/Edit-Variable——只不过被调试的程序是智能本身（Debug Intelligence / Time Travel Inside AI）。
> 用户路径：**Workflow（在完成什么）→ Decision（为什么这么做）→ Microscope（token 级细节）→ Experiment/Debug（接管控制）**。
> 本计划取代《视觉密度升级-开发计划》的排期；该计划中的视效想法（概率光渊等）降级为 Microscope 层的候选增强，数据与结论仍有效。

## 0.5 · Debugger 能力模型（产品核心，凌驾一切镜头）

调试工具条（Workspace 顶部常驻，对标 DevTools 断点栏）：

```text
▶ Run   ⏸ Pause   ⏭ Step   ↩ Back   🌱 Fork   🎲 New Seed   🎛 Temperature
```

能力分两档，诚实区分、逐步交付：
- **Replay-Debug（地基已就绪）**：对已完成的 trace 任意步暂停/单步/回退，检查当时全部状态（候选/概率/熵/耗时），从任意步改选 token / 换 seed / 改温度后**真实续跑**出新宇宙并存档对比——Replay 不是播放，是「暂停→改状态→继续→保存新宇宙」。
- **Live-Debug（新能力，Sprint 4 交付）**：生成进行中实时断点——正在写到第 N 个 token 时 Pause，看模型此刻的候选分布，改 sampling 参数或改选 token 后 Continue。worker 已有 interrupt 雏形，逐 token 生成循环天然支持每步检查暂停点。
- 铁律不变：每个可修改的变量都是真实采样参数；修改后的未来由同一模型真实续跑，永远标注「模拟续跑 · 非原始记录」；.aitrace 是存档格式，每个新宇宙都是一份可再调试的存档。

## 0 · 三层混淆的诊断（本次重构的出发点）

| 层 | 问题 | 现状 |
|---|---|---|
| 第一层 Token | AI 怎么生成一个 token | 做得最多（柱阵/Inspector/熵/字幕），却被放在首页 |
| 第二层 Workflow | AI 怎么完成一个任务 | **完全缺失**——普通用户真正想看的层 |
| 第三层 Decision | AI 为什么做这个决定 | 零散（犹豫点/决策 chips），没有统一入口 |

普通用户看 `the 0.62 / 0.18 / 0.07` 的反应是「所以呢？」；看「✔ 理解问题 → ✔ 推导方案 → 正在写答案」马上就懂。首页必须是后者，前者藏在下钻第三层。

## 1 · 新信息架构（四层导航，取代现有并列页签）

```text
Observe      观察 AI 在干什么     Conversation / Workflow / Timeline / Performance
Explain      解释为什么           Decision / Reason / Confidence / Alternative
Microscope   最底层               Token / Entropy / Sampling / 现有全部解剖镜头
Experiment/Debug   接管控制    ▶⏸⏭↩ 断点 / Temperature / Seed / Fork / Replay-Debug / Live-Debug
```

- 现有页面全部**收编不删除**：实验台主视效、Inspector、此刻卡、思路地图、没走的路 → Microscope/Explain；分岔、seed、温度 → Experiment；实验档案/成绩单 → Observe·Performance。
- 每层向下埋一个钩子（认知阶梯）：Workflow 步骤卡可点 → Decision 卡 → 「看这一步的 token 级证据」→ Microscope → 「亲手改一个变量」→ Experiment。
- `.aitrace` 是四层唯一数据源：同一份 trace，四种分辨率。

## 1.5 · 首页定调：AI Workspace 工作现场，不是聊天页（创始人 2026-07-24 补充定调）

> 产品卖的是「AI 正在工作」而不是「AI 正在聊天」。竞争对手不是 ChatGPT，
> 而是 Chrome DevTools / Wireshark / NVIDIA Nsight / Task Manager——观察一个系统如何运行的工具。

- **硬判据**：遮住输入框，页面必须依然成立——没有输入也能浏览历史 .aitrace、回放推理、看性能、分析 Agent 工作流、比较两次实验。
- **首页 = 控制台（Control Center）**，像 IDE 而非聊天窗口：

```text
AI Workspace
├─ Current Run   当前任务（等待输入… / 运行中第 N 步）
├─ Activity     AI 正在干什么（§2 三级证据的步骤清单）
├─ Timeline     执行时间线（可回放）
├─ Trace        本次/历史 .aitrace（无运行时 = 档案入口）
├─ Performance  GPU/WebGPU 状态、首字延迟、吞吐、显存
└─ [ Ask AI ]   输入框只是启动一次 Run 的入口，不是主角
```

- 用户输入后整个 Workspace 才「活起来」：各面板随真实运行实时推进。
- **命名去聊天化**：不用 Chat/Conversation；用 Workspace / Run / Session / Mission / Execution。多轮对话能力保留，但叙事是「同一个 Session 里的多次 Run」。
- 首页一句话从「我来回答你的问题」改为「**来观察 AI 怎么完成你的任务**」。

## 2 · Workflow 阶段划分的诚实性方案（Sprint 1 的核心设计难题）

阶段标签不许拟人臆测。三个证据等级，逐级降级、诚实缺席：

1. **事件级（最强）**：trace 里有 agent 事件（tool_call/handoff/decision_point）→ 阶段直接由事件切分，标签用事件原文。
2. **结构级**：`<think>`/`</think>` 边界 + 熵拐点（思路地图已验证的算法）→ 阶段=「思考中/写回答」，细分站名走白名单（审题/权衡/展开/收束）。
3. **运行级（兜底，永远存在）**：pipeline 实测（加载→tokenize→prefill→逐 token 解码→完成）+ 实时吞吐——这些是任何生成都真实存在的阶段，零臆测。

UI 呈现统一为「步骤清单 + 当前步高亮 + ✔ 已完成」，标签后带出处徽章（事件/结构/运行）。没有更高等级证据时只显示低等级——宁可粗，不可编。

## 3 · Sprint 排期

### Sprint 1 · AI Workspace 控制台（新首页，P0）

- [ ] 1.1 Workspace 布局（§1.5）：Current Run / Activity / Timeline / Trace / Performance 五面板 + [Ask AI] 入口；未运行时各面板呈现真实静态（设备就绪/历史档案/等待任务），遮住输入框页面依然成立。
- [ ] 1.2 多次 Run（Session 内连续使用）：每次 Run 产出独立 trace 自动归档；上下文按 Session 历史拼接（KV/显存如实提示）；命名去聊天化。
- [ ] 1.3 Activity 面板：按 §2 三级证据渲染当前 Run 的步骤状态（进行中/已完成/耗时），生成中实时推进。
- [ ] 1.4 Performance 面板：首字延迟 / tokens/s / 总耗时 / 设备与显存（全部实测），每次 Run 一行可横向比较。
- [ ] 1.5 导航重构为 Observe/Explain/Microscope/Experiment 四层；旧页签收编映射。
- [ ] 验收第一条：新访客 5 秒内能答出「这是 AI 的控制台，来观察 AI 怎么完成任务」；遮住输入框页面成立；可连续多次 Run 考验性能；每步状态有出处徽章。

### Sprint 2 · Decision Layer（Explain 层，P0）

- [ ] 2.1 步骤卡点击 → Decision 卡：这一步做了什么（事件/结构原文）、有哪些选择（该步 topk / 候选事件）、为什么放弃（真实概率差/事件 reason，缺失就写「未记录」）。
- [ ] 2.2 收编犹豫点/决策时刻/没走的路为 Decision 卡的证据区块。
- [ ] 2.3 Confidence 只用实录字段（prob/事件 confidence），无则缺席。

### Sprint 3 · Microscope 收编（P1）

- [ ] 3.1 现有柱阵/Inspector/此刻卡/字幕/思路地图整体迁入第三层，入口=Decision 卡的「看 token 级证据」。
- [ ] 3.2 视觉密度增强（概率光渊光丝束）在此层按原方案择机实施。

### Sprint 4 · Experiment → Debugger（P0⬆，产品核心差异化）

- [ ] 4.1 调试工具条（§0.5）常驻 Workspace：▶/⏸/⏭/↩/Fork/Seed/Temperature，全部接真实能力，不做假按钮。
- [ ] 4.2 Replay-Debug：现有 replay/fork/seed 收编为「暂停→检查→修改→续跑→存新宇宙」闭环；新宇宙自动归档可对比可再调试。
- [ ] 4.3 Live-Debug：生成中实时断点——worker 逐 token 循环加暂停检查点（interrupt 机制扩展）；Pause 时展示当前候选分布，支持改 sampling 参数/改选 token 后 Continue；改动点记入 trace（事实不丢）。
- [ ] 4.4 从任一 Decision 卡一键「改这个变量重跑」。

### Sprint 5 · RAG 插进 Workflow（P1）

- [ ] 5.1 检索作为 Workflow 的一步呈现：`Searching… → Found N → Selected K → Discarded N-K → Reason`，每步可点。
- [ ] 5.2 Decision 卡回答：为什么引用这段/没引用哪些/有没有误引用/引用后答案变了什么（配 fork 对比）。
- [ ] 5.3 trace 规范：检索事件字段（query/候选+各路得分/选中+落选/送入上下文片段）；纯前端实现（本地文档+浏览器内 embedding 或 BM25），零后端不变。
- [ ] 不做独立指标页；Recall/Precision 类指标只进 Performance 的专业下潜。

### Sprint 6 · Agent = Workflow 升级（P2）

- [ ] 6.1 工具调用（检索/浏览器内可行的工具）串进同一条 Workflow：收到任务→制定计划→调用工具→等待结果→继续→完成。
- [ ] 6.2 步骤下钻见 Thought/Decision/Tool/Latency/Token；双模型接力（已有 handoff 字段）作为其中一种工具形态。

## 4 · 不变的铁律

- 每个数字/状态/标签必须有 trace 或实测来源；证据不足降级呈现，绝不拟人编造。
- 一句话答案「亲眼看 AI 完成任务的全过程」必须在首页 5 秒自证。
- 验证序列全绿 + 设计决策卡 + 看板更新 + 写回本机，每期照旧。
