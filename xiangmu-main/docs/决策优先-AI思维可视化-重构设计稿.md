## 0. 一句话定调

**可视化对象从 Token（模型内部变量）升级为 Decision（一步决策为什么发生）。**
Token、概率、熵、检索、耗时都只是素材；主角是「AI 这一步为什么这么写」。
配套新原则：

**P26 · Meaning over Data（先看到意义，再看到数据）**
用户任何时候都不应该只看到「数据」，而应该直接看到「意义」。每一个视觉元素必须能回答四问：
1. 这是什么？
2. 为什么会出现？
3. 它说明 AI 正在发生什么？
4. 用户看完这一眼，获得了什么新的理解？
回答不了四问的元素 = 装饰，删除。P25 管「像素必须有证据」，P26 管「证据必须翻译成意义」，两者互为表里。

## 1. 调研综述（借什么 / 不借什么）

| 案例 | 它做对了什么 | 我们借 | 我们不借 |
|---|---|---|---|
| **logprob 可视化工具**（gekro Token Probability Visualizer、bradsjm/logprob-visualizer、Streamlit logprob demo） | token 按置信度着色、点击看 top-K 候选、序列级统计（均值/最不确定步） | 「最不确定的一步」作为整段摘要入口；置信度着色语义（绿=笃定，暖=犹豫） | 止步于数据表格——它们回答「概率是多少」，不回答「所以呢」。这正是我们要超越的层 |
| **Anthropic circuit tracing / attribution graphs**（transformer-circuits.pub, Neuronpedia） | 把「AI 为什么这么想」定义为可追踪的计算路径；官方隐喻就是「AI 显微镜」 | 叙事框架：我们做的是行为级显微镜（决策证据），他们做神经级（特征回路）；界面上明确分层「行为层已可见 / 神经层待导出」 | 不伪造特征/回路——我们没有 attention/hidden state 数据，此层诚实缺席（P9） |
| **Transformer Explainer**（poloclub）/ **bbycroft llm-viz** / **Anatomy of an LLM** | 把 Embedding→Transformer→Logits→Softmax→采样整条数据流做成活的主舞台；证明「全词表投票」可以被普通人看懂 | 「生成一步 = 全词表投票收敛」的场景叙事，纠正「词海=数据库挑词」的误导 | 他们用教学模型跑固定流程；我们用用户此刻的真实 trace，每个数字都是本机实测 |
| **Chain-of-thought UI 组件**（assistant-ui、ai-sdk elements、各 Reasoning 组件） | 把推理过程分组成「步骤事件」：状态、折叠、点击展开，业界已收敛的交互范式 | 决策日志的交互形态：事件卡片 + 状态 + 点击回到那一刻 | 它们展示的是模型自述的 CoT 文本（不可验证）；我们展示的是采样层证据（可验证），文案上要划清 |
| **Agentic RAG UI**（Nexla canvas panel、agentic-rag-assistant） | 引用角标 chips + 活动时间线 + 来源面板 + 相关度分数；「AI 刚去找了资料」全程可见 | RAG 决策的舞台化：检索发生时页面形态改变（文档飞入→命中/弃用→引用高亮），不是右侧安静列两个 Source | 无 |
| **Distill《Building Blocks of Interpretability》** | 可解释性界面 = 原语组合：是什么 × 有多强 × 为什么；单一图表永远不够 | 四问检验表的方法论来源；决策事件 = 多个证据原语的组合体 | 无 |

**调研结论**：市面上「数据可视化」（logprobs 工具）和「机制可视化」（Anthropic）两头都有人做，但「**决策叙事可视化**——把真实采样证据实时翻译成普通人能读的故事」没有人做。这是我们的位置。

## 2. 六个重构（每项均通过四问检验，标注驱动字段）

### A. 决策流（Decision Stream）替代 Token 流

生成的基本叙事单位从 token 改为**决策事件**。由真实字段自动分类（全部现有数据，无新采集）：

| 事件类型 | 判定（真实字段） | 人话模板 |
|---|---|---|
| 必然 | `topk[0].prob > 0.9` 且选中 rank1 | 静默，不生成事件（合并为「顺写了 N 个字」） |
| 掷硬币 | top-2 差 < 5% 且 top1 > 5%（与 closeSteps 同口径） | 「它几乎是掷硬币：『A』和『B』各约 X%，这次抽中了『A』」 |
| 温度改命 | 选中 token rank > 1 | 「温度 T 让它没选第一名『A』(X%)，抽中了第 R 名『B』(Y%)」 |
| 想法很散 | entropyLevel ≥ 0.7 | 「这一步它的候选最分散（熵 X nats），几十个词都有机会」 |
| 卡住了 | `dt` > 全程均值 × K（K 取 3） | 「这一步花了平时 K 倍的时间」 |
| 去查资料 | RAG 子运行事件 | 「它先检索了 N 篇，用了 M 篇，弃了 N−M 篇」 |
| 接力交棒 | model_handoff 事件 | 「规划由模型 A 完成，执行交给模型 B」 |

四问：这是一次决策 / 因为真实字段命中阈值 / AI 正在竞争选择或引用外部证据 / 用户理解「AI 是逐步抽签而非整句想好」。

### B. 内心独白 → 决策日志（人话化）

现状「第68步 犹豫『本身』差 0.00%」是 AI 术语。改为 A 表的人话模板 + 展开显示放弃的候选原文与概率；每条日志点击 = 回放跳到那一刻（沿用现有跳步能力）。术语（熵/rank/nats）降级为事件卡展开后的「查看证据」层。命名从「内心独白」改为「**它刚才做了什么**」（内心独白有拟人化嫌疑，且用户误以为是自己的独白）。

### C. 词海 → 全词表投票场景

**问题**：现在的词海视觉 =「从仓库里挑词」，暗示数据库/字典检索——这是对 LLM 的误导。
**改法**：一步生成的大场面改为三拍（≤600ms，reduced-motion 直接呈现终态）：
1. **亮起**：背景以极低亮度暗示整个词表（151k 词，文案标注真实词表大小），代表全体投票；
2. **收敛**:只有 top-k（真实 `topk[]`）浮出成可读的词，亮度/大小 = 真实概率；其余以「尾部质量 X%」一条真实数字带表达（现有字段）；
3. **落定**：胜者凝聚落入正文（现 BirthScene 复用），说明行「几十万个词一起投票，最终『X』胜出（Y%）」。
四问全过；驱动字段：`topk[]`、尾部质量（1−Σtopk）、`entropy`、词表大小（模型元数据）。

### D. 3D 柱林可读性 + 柱子生命体化

**先修可读性**（你截图里的三个问题）：
1. 词标签相互重叠、和 tooltip 互挡 → 默认只显示当前步 + 犹豫点的词，其余 hover 才出；标签碰撞避让；tooltip 固定到底部信息条而不是浮在词上。
2. 词太小看不清 → 当前步词放大置顶；镜头默认距离拉近一档。
3. 「词沉到 Z 轴下方像词海」→ 结合 C：落选候选沿 Z 轴下沉衰减（透明度=真实概率），形成「被放弃的词沉下去」的可读隐喻——每个下沉的词都是真实候选，不加装饰粒子。

**生命体化**（每个动效挂真实字段，缺字段的不做）：

| 动效 | 驱动字段 | 缺席处理 |
|---|---|---|
| 柱体震颤幅度 | `entropy`（entropyLevel） | — |
| 顶部浮出候选 | `topk[]` | — |
| 明暗呼吸 → 禁止 | 无字段 | 不做（P24 禁呼吸光） |
| 底部注意力连线 | attention 张量 | 主模型暂无导出，诚实缺席，写进升级路线 |
| 生长速度 | `dt` | — |

### E. RAG / Agent 决策舞台化

开启联网检索时页面形态必须改变：Prompt 发出 → 检索调用卡片实时出现（真实 query 原文）→ 结果文档飞入（真实标题/URL）→ 命中高亮、弃用变暗下沉（真实选用/放弃记录）→ 正文引用处角标 chips，点击回到该文档。失败也如实入档（ok:false 卡片红色静止）。驱动字段：现有 RAG Observatory trace 事件，无新采集。

### F. 全流程「活着的数据流」（远期，依赖导出）

Prompt→Embedding→Transformer→词表投票→Token 的整条活流水线（对标 bbycroft/Transformer Explainer 但用真实 trace）。当前只有采样层数据，故本期只做 C（词表投票段）；Embedding/Transformer 段等注意力/隐层导出后再点亮，界面上以「未点亮的暗段 + 『此段证据待导出』」诚实呈现，而不是画假的。

## 3. 诚实边界（P9）

能回答的「为什么」：它同时考虑了谁、放弃了谁、差多少、是必然还是抽签、seed/温度的作用、这一步花了多久、去查了什么资料、用了哪条弃了哪条。
不能回答的「为什么」：神经层面为何想到这些候选（需要 attention/hidden state/特征回路）。此层界面上明示「行为层证据 · 神经层待导出」，升级路线 = ONNX attention 导出（`tools/export_attention_onnx.py` 已验证可行）。

### 5.2 修正后吸收（与宪法/数据现实冲突，给出替代）

| 纲领条目 | 冲突 | 裁决 |
|---|---|---|
| 背景「呼吸式」脉动、呼吸节奏条 | P24 禁呼吸光/循环装饰动效 | 背景流场幅度只由逐步真实熵驱动（现 EvidenceField 口径），生成结束即静止；不做无数据的周期性呼吸 |
| 「随机波动、杂色烟雾」表达犹豫 | P9/P25 禁随机 noise | 湍流形态由真实 entropy 序列确定性生成，无随机数 |
| 注意力连线/粒子流向、隐藏状态/嵌入色彩空间、logits 柱形 | 主模型暂无 attention/hidden state 导出；logits 仅深度采集模式有 top-256 快照 | 写入远期（F），界面以「此段证据待导出」暗段诚实呈现；logits 柱形在深度采集开启时点亮（已有 DeepCapture 字段） |
| 粒子爆炸、激光束、画面旋转等「震撼档」 | P24 禁弹跳/超 600ms/装饰性大场面 | 惊艳档保留但限幅：单次 ≤600ms、只由导演系统真实犹豫点触发、预算限次（一直爆=没有爆） |
| WebSocket/REST 实时后端流 | 本产品纯浏览器本机推理，无后端 | 统一消息格式的思路采纳：浏览器内生成循环→UI 的逐步事件流（现有 TokenStep 回调）即等价物，无需网络层 |
| 多用户协作观察 | 超出当前产品边界 | 不入本期；.aitrace 导出/导入回放已提供异步协作的最小形态 |
| 近义词群色彩（语义聚类） | 需要 embedding 数据 | 随 hidden state 导出一并入远期 F |
