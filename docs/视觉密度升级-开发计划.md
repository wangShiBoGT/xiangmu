# 视觉密度升级 · 开发计划（概率光渊 / 幽灵续句 / 注意力聚光灯）

> 触发：用户反馈「柱子还是太单薄了」，并给出参考图（发光丝线汇聚 + 幽灵岔句悬垂）。
> 定位：把参考图的视觉语言融合进现有主视效与「没走的路」，不是重做一个页面。
> 铁律不变：每根线、每个数字都要有真实 trace 来源；无数据诚实缺席；「看懂优先于酷炫」——每个新视效必须让用户多懂一件事。

## 第 0 条铁律 · 产品是干什么的（负责人视角，凌驾一切视效决策）

访客打开页面第一秒心里的问题是「**这产品是干什么用的？**」。答案必须一眼可得：

> **亲眼看 AI 写下每个字时的真实抉择。**
> 你问一句话，它在你的浏览器里真实推理，把每一步的候选、概率、犹豫、差点走的另一条路原样记录给你看。

执行约束：
- 每个镜头验收前先问：「它帮用户回答了『这是干什么的』吗？」答不上就砍掉或收起。
- 首屏（Hero + 主视效前 5 秒）必须自证这句话，不依赖任何说明文档。
- 本计划所有 Sprint 的验收标准第一条一律是这个问题。

## 0 · 参考图的视觉语言拆解（世界级产品的三个共性）

| 元素 | 参考图做法 | 它让用户懂了什么 |
|---|---|---|
| 发光丝线束 | 几十根细线从一个焦点散开/汇聚，粗细亮度不同 | 「很多可能性中选了一条」——密度本身就是信息 |
| 焦点高亮词 | 句中关键词金色发光，其余暖白 | 「此刻的主角是谁」 |
| 幽灵悬垂岔句 | 主句居中，犹豫点垂下暗淡虚线短句+概率 chip | 「差一点就是另一句话」 |
| 底部诚实脚注 | 「无记录时此镜头诚实缺席」 | 信任感：这不是动画，是记录 |

现有主视效的问题：柱子只表达「每步一个概率值」，把 top-k 的**竞争过程**（8 个候选彼此拉扯、落选者消散）压缩没了——单薄的根源是**信息密度低**，不是柱子不够粗。

## 1 · Sprint 10「概率光渊」——主视效从柱阵升级为光丝束（P0）

把每一步渲染成一次「多丝线竞争 → 一根胜出」的事件，柱子退为底轨。

- **10.1 数据层 `lib/lightWeave.ts`（纯函数+测试）**：由 `steps[].topk` 生成每步的丝线束几何描述——每根丝线对应一个真实候选：粗细=prob、亮度=prob^γ、终点=下一步锚点（仅胜者延续）、落选丝线在该步后按概率衰减下垂消散（参考图的散开束）。熵高的步丝线自然发散，熵低的步自然收拢成一股——**分布形态直接成为视觉形态，无需任何人为夸张**。
- **10.2 渲染层（Three.js，改造现有 InstrumentCluster，不新建场景）**：
  - 主线（胜者链）：暖金主丝，连续贯穿全程，粗细随 prob 呼吸；
  - 落选丝：青灰短须，长度∝prob，向下垂散后 fade（参考图下垂岔线）；
  - 犹豫点（closeSteps 命中）：两根近等粗丝线并行一小段再分开——「差点走另一条」第一次在主视效里直接可见；
  - 熵峰步：丝束最散处加琥珀微光（复用现有 ◆ 熵峰口径）。
- **10.3 焦点词联动**：当前步的句内 token 金色发光（参考图焦点词），丝束视觉焦点与句子焦点同一个词——此刻卡/字幕/丝束三处读数同源。
- **10.4 图例与人话**：左下角一句话图例「一根丝 = 一个真实候选 · 粗细 = 概率 · 散开 = 它在犹豫」；hover 任一丝线显示候选 token+概率（来自 topk 实录）。
- **验收**：任意步丝线数 = 该步 topk 实录条数；丝线粗细排序 = 概率排序可交叉核对；犹豫点/熵峰与 closeSteps/entropy 完全一致；60fps（229 步 × ≤8 丝，用 instancing/合并 geometry）；验证序列全绿。

## 2 · Sprint 11「幽灵续句」——没走的路升级为参考图布局（P1）

- **11.1 布局重排**：主句暖白居中横排；犹豫点处菱形节点 + 概率 chip（真实 top-2 落选概率）；落选候选以暗淡虚线从节点悬垂（参考图下半）。标题沿用参考图叙事：「这句话，差点变成另外 N 句」（N=实测 closeSteps 数）。
- **11.2 幽灵续句文字的诚实边界（关键决策）**：参考图里岔句有完整后续文字——**我们只在真实续跑后显示**。「试跑那个宇宙」跑完的分支句作为幽灵句挂到对应节点下；未试跑的节点只显示落选 token 本身 + 「后续未记录 · 点击试跑」。绝不预先编造岔句文字。
- **11.3 试跑结果回填**：fork 完成后分支 trace 的前 ~12 token 渲染成悬垂幽灵句，标注「模拟续跑 · seed=N · 非本次记录」，点击进入完整分支对比（复用现有分支视图）。
- **验收**：无续跑时页面上不存在任何未记录文字；chip 概率=trace 实录；续跑句可复现（同 seed 同输出）；验证全绿。

## 3 · Sprint 12「注意力聚光灯」——依赖数据落地，UI 规格先冻结（P2·暂搁待数据）

Sprint 9 调研结论（见 `docs/Sprint7-9-设计决策卡.md`）：现用 ONNX 导出不含 attention 张量，**现在做连线就是伪造**。本期只做两件事：
- **12.1 UI 规格冻结**（按参考图上半）：问题句/回答句上下两行，当前词→源词发光连线（粗细=实测权重，主焦点琥珀、次焦点青绿），右侧权重读数卡 top-3 条形+数值，标题模板「写这个词时，它盯着你问题里的『X』」，底部脚注「连线粗细=该层注意力实测权重 · 无记录时此镜头诚实缺席」。规格入决策卡，数据一到即可实装。
- **12.2 数据路径立项**：重导出带 attention 输出的 ONNX（仅末层、top-N 截断）→ `.aitrace` `extensions.attention` 落字段。在此之前该镜头整体缺席。

## 3.5 · Sprint 13「双模型 Agent 工作流」——两个模型协作全程可观察（P1，可与 Sprint 11 并行规划）

> 现有底座已备好：`.aitrace` 已有 `agent` 事件（tool_call / tool_result / decision_point / **model_handoff**）与 `modelSegments`（每段 token 归属哪只模型），AgentTimeline 色带已能锚定事件。缺的是**真实产生这些事件的运行时工作流**与配套镜头。

### 13.1 工作流设计（负责人视角的完整流程）

```text
用户提问
  → 【规划模型】（小模型，如 Qwen3 0.6B）生成「怎么答」：拆解问题 / 决定是否需要工具 / 写出执行指令
      每个 token 照常进 trace；关键决定记 decision_point（reason 原样保留）
  → model_handoff 事件（from 规划模型 → to 执行模型，atStep 锚定交接点）
  → 【执行模型】（主模型，如 GLM-Edge/DeepSeek 蒸馏）接过规划产物作为上下文，生成正式回答
      每个 token 照常进 trace
  → 单一 trace 收尾：一条 token 时间线贯穿两个模型，谁写了哪段、为何交接全部可回放
```

加载策略（诚实面对浏览器显存）：
- **默认「接力式」**：规划模型跑完即 dispose 再载执行模型（现有 worker 已支持换载），显存峰值≈单模型；交接期的加载耗时如实记进 pipeline 计时，不假装无缝。
- **可选「双驻留」**：显存充裕（navigator.gpu 探测 + 用户显式开启）时两模型同驻两个 worker，交接零等待。能力不足时该选项灰掉——诚实缺席，不静默降级。

### 13.2 匹配的可视化（每个环节选一个已验证的视觉语言）

| 流程环节 | 镜头 | 视觉语言（全部复用既有词汇） |
|---|---|---|
| 谁在写这段 | **双泳道色带** | AgentTimeline 升级：token 轴按 modelSegments 分色（规划=青绿 / 执行=暖金），一眼看清「前 N 个 token 是规划模型写的」 |
| 交接瞬间 | **交接节点卡** | 时间线上菱形节点，点击展开玻璃卡：from/to、note/reason 原文、交接时刻的 pipeline 耗时——沿用此刻卡语言 |
| 规划的决策 | **决策时刻 chips** | decision_point 进现有 ActivityLog/决策 chips，reason 缺失就不显示不估 |
| 规划→执行的落差 | **对照镜头** | 上行：规划模型的指令原文；下行：执行模型实际写出的句子；Sprint 10 光丝在交接点换色续接 |
| 全程一句人话 | **思考字幕扩展** | 交接步字幕模板：「规划完毕，把答案交给 X 来写」（字段驱动：handoff.to） |

### 13.3 任务拆解

- [ ] 13.3.1 worker 增加 pipeline 运行模式：两段生成（规划 prompt 模板 → handoff → 执行），产出单一 trace（steps 连续 + agent 事件如实记录）；接力式换载优先。
- [ ] 13.3.2 `modelSegments` 双泳道色带渲染 + 交接节点卡（复用 AgentTimeline，不新建时间线）。
- [ ] 13.3.3 决策 chips / 思考字幕 / 此刻卡的 handoff 模板接入（全部字段驱动）。
- [ ] 13.3.4 双驻留能力探测与开关（能力不足灰掉）。
- [ ] 13.3.5 验收：第一条=「用户能否一眼答出这是干什么的」；trace 可回放且两段归属可交叉核对；单模型 trace 不出现任何 agent 镜头（诚实缺席）；验证序列全绿。

## 4 · 设计基调（三个 Sprint 共用）

- 色板：暗底 `#05070d`，主丝暖金 `#e8c47a`，次焦点青绿 `#5fd4b0`，幽灵青灰 `#3a4a55`，警示琥珀 `#f0a848`（与现有 AODL 视觉 DNA 一致，不引入新色系）。
- 动效：丝线用 additive blending + 微呼吸（周期≥3s，幅度≤15%），拒绝无信息的粒子雨；所有发光强度映射真实概率，不做装饰性辉光。
- 排期：Sprint 10（主视效，约一次交付）→ 11（幽灵续句）→ 13（双模型 Agent 工作流）→ 12（等数据）。每期验证序列全绿 + 设计决策卡 + 看板更新 + 写回本机。

## 5 · 风险与对策

- 性能：光丝几何量 ≈ 229×8，用 BufferGeometry 合批，实测 fps 进验收。
- 可读性回退：光丝模式若用户看不懂，保留柱阵为可切换旧视图（一个 toggle，不删代码）。
- 最大风险是「好看但没人懂」：每个镜头上线前过一遍铁律——能否一句人话说清「这在告诉你什么」。
