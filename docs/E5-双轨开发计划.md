# E5 双轨开发计划（AODL 治理版）

> 定位：本文**不废除**《直通 E5 完整规划》的任何锚点定义（DS/C3/D5/D6/E1–E5 仍是事实源），
> 只做两件事——① 把它的"批次 5→10 一路开发"节奏，**重排**成"双轨 + 三阶段"；
> ② 给每个模块的开发**加一道 AODL 闸门**。变更先改本文再动代码。
>
> 一句话动机：**AI Observatory 不是 CRUD SaaS，是一个新品类。** 新品类的护城河不是"功能多"，
> 是"一个别人没想到、且体验极其统一的核心认知"。所以现在不追求"功能开发完成"。

---

## 0 · 为什么改节奏（品类产品的路径）

> **NRP 住址**：本节是"品类产品路径（Figma/Notion/Cursor 案例）"的**唯一住址**。其它文档引用此论点时写 `See E5-双轨§0`，不复述。

世界级新品类产品都不是"先把功能做全再统一"，而是先证明一个核心体验：

| 产品 | 先证明的核心体验 | 后来才扩展 |
|---|---|---|
| Figma | 浏览器里的设计软件真的更好 | Dev Mode / Slides / AI / Variables |
| Notion | Block 是一种新的信息组织方式 | Calendar / Wiki / Projects / AI |
| Cursor | Tab 自动补全真的改变写代码 | Agent / Background / Rules / Memories |

共同路径：**一个核心体验 → 验证 → 形成设计语言 → 扩展能力**。不是"功能全开发 → 再统一"。

**我们要防的最大风险**：若现在并行开发 Benchmark/Agent/Branch/Workflow/3D/Archive/Discovery，
半年后会发现每个模块像不同的人设计的——**哪怕都是你自己**，因为今天的你和半年后的你已不是同一个设计师。
AODL（认知栈 + Visual/Cognitive DNA）的价值不在今天，在半年后仍能保证所有东西像同一个产品。

## 1 · 双轨并行（Two Tracks）

```text
轨道一 · 做（唯一近期上线验证物）
   把当前 Core Loop 打磨到「第一次使用就产生"原来 AI 是这样工作的"的瞬间」
        ‖  并行
轨道二 · 写（不写代码）
   把 E1–E5 的体验 / 交互 / 文案 / 动画 / 认知路径全部设计到纸面
```

好处：等真正开发 Benchmark/Agent/Branch 时，它们不是临时想到的功能，
而是**早已属于同一个世界观、同一种设计语言、同一套认知体系**的一部分——不返工。

## 2 · Core Loop 定义与「第一次使用震撼」验收（轨道一的靶心）

**Core Loop（核心闭环）**：

```text
提出一个问题 → Replay → 看到 Token → 发现概率 → 理解 AI → 继续实验
```

它是 Cognitive DNA「观察阶梯」的产品化身（见 `AODL/01-Cognitive-DNA.md §2`）。轨道一的唯一目标：
让首访用户在一次会话内走完阶梯、并在阶 5 说出「原来 AI 是这样」。

**「震撼」不是形容词，是可检验的认知验收**（复用 Cognitive DNA §3）：

| 认知阶 | 首用应发生 | 当前差距（Phase A 待体检填写） |
|---|---|---|
| 阶0 困惑 | 首屏就撞见反常现象（同问两答/候选仅差 X%）| 待走查 |
| 阶1 信任 | 第一次发现"任何一句话都能点开是真证据" | 待走查 |
| 阶2 探索 | 发现"还能往下钻/换 seed" | 待走查 |
| 阶3 因果 | 亲手改一个字/滑温度，看见后面分岔 | 待走查 |
| 阶4 复现 | 同 seed 重放逐 token 一致 | 待走查 |
| 阶5 结论 | 用户自己说出"原来 AI 是这样" | 待用户测试验证 |

Phase A 的工作就是**逐阶补齐差距**，不加任何新功能。

## 3 · 三阶段（Phase A / B / C）

### Phase A（现在）· 100% 不写新功能

**只做**：Core Loop 打磨 · Visual DNA · Cognitive DNA · AODL · 产品原则 · 用户测试。
**目标**：第一次使用震撼（§2 认知阶梯全部达标）。

具体动作（全部围绕已有 Core Loop，零新功能）：
1. 用「观察阶梯」对现有首屏→实验台→双结局→档案做**逐阶 gap 分析**（填 §2 表）。
2. 只修阻碍"首用震撼"的缺陷：可点开性不明显、下钻入口发现不了、犹豫点到双结局路径太长（C3.1 属此类，因为是"缩短已有承诺的兑现"，非新功能）。
3. AODL 校准切片定稿（Visual/Cognitive DNA）。
4. 一轮真实首访用户测试，记录他们在哪一阶掉队。

> 边界：C3.1「犹豫点一键双跑」放进 Phase A，因为它不引入新推理路径、只是把已有承诺的兑现少一步（P4）；
> 其余 D6/E1–E5 一律不在 Phase A。

### Phase B · 未来功能只做纸面设计（不写代码）

在 `Design/Future/` 下，把 E1–E5 + D6 的**体验/流程/文案/动画/认知路径**写完，Markdown + Mermaid，无 TS/CSS。
每个模块按统一模板（见 §5）回答：用户第一次/第二次/第三次/第五次进入分别发生什么。

Phase B 产出物是"体验稿"，不是 PRD——它先过 AODL 六层栈自检，尤其 Layer 1 认知阶梯：
**这个未来模块在用户认知里接哪一阶、埋哪个下一阶的钩子。**

### Phase C · 真开发（每模块先过五闸）

任何模块写第一行代码前，必须逐条通过：

```text
□ 符合 AODL 六层栈吗？（能写出它落在哪层、依据哪条）
□ 符合 Product Constitution 吗？（P1–P24 + 词表）
□ 符合 Evidence First 吗？（每个数字可下潜到真实 trace）
□ 符合 Cognitive DNA 吗？（接认知阶梯哪一阶、埋哪个钩子）
□ 符合 Product Grammar 吗？（填满 Question→Evidence→Interaction→Conclusion→Replay 五行）
```

五闸缺一即不开发。开发后仍按既有交付纪律：代码+测试+验收记录+写回校验+四项自查+"最可能死掉的方式"回照。

## 5 · `Design/Future/` 目录约定

```text
Design/
  Future/
    README.md            ← 本目录说明 + 体验稿模板
    _模板-体验稿.md       ← 每个未来模块照此填写
    E1-规则包目录/
    E2-分享链接/
    E3-多模型对比/
    E4-Agent观察/
    E5-采样显微镜/
    D6-成绩单页/
```

只放 Markdown / Mermaid / 流程图 / 体验稿，**不放 TS/Vue/CSS**。像 Apple 的功能——设计早两年，代码晚两年。

体验稿模板（每模块必答）：
1. **它接认知阶梯哪一阶**（Cognitive DNA §2）+ 埋哪个下一阶钩子；
2. **首次/二次/三次/五次进入**分别发生什么（认知随访问次数怎么长）；
3. **产品语法五行**（Question→Evidence→Interaction→Conclusion→Replay）；
4. **数据来源**（哪条真实 trace/测量；无真数据的能力如实不做）；
5. **动画类别**（空间/时间/因果/注意四类之一，时长档 150/300/600）；
6. **文案**（过词表；拟人词只作索引）；
7. **AODL 依据**（能回溯到六层栈的具体条目）；
8. **最可能死掉的方式**（失败判据）。

## 6 · 三视角自评（写完先自我攻击）

**产品负责人**：双轨最大风险是"轨道二写太多、轨道一没打磨够"——纸面设计上瘾、迟迟不验证核心体验。
对策：Phase A 有硬门槛（首访用户测试真实走完认知阶梯）才允许把重心移向 Phase B。

**老板**：Phase A 不产出新功能，短期"看起来没进展"。但 Core Loop 的首用震撼是**唯一**能对外传播、
能验证品类假设的东西；一个震撼的 Core Loop 比五个平庸模块更有说服力。D6/E5a 的纸面稿可作为对外叙事素材。

**投资人**：这个节奏正是 Figma/Notion/Cursor 早期的节奏——先证核心、再形成语言、后扩展。
AODL 是"体验统一性"这条长期壁垒的显性资产；纸面先行让扩展期零返工，是资本效率最高的做法。

**未决问题（诚实列出）**：
1. Phase A "首用震撼"的用户测试口径未定（几人、什么背景、算不算达标的阈值）——Phase A 首日先定测试协议。
2. C3.1 归入 Phase A 是唯一"擦边"判断，若走查发现它其实需要新交互，则退回 Phase C。
3. `Design/Future/` 与既有 `docs/` 规划文档的边界：Future 只放"未来模块体验稿"，已上线能力的规划仍在 docs/。
