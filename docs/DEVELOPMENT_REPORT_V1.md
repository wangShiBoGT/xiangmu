### 2. 产品重新定位

#### 旧定位（❌ 错误）
- "AI 幻觉检测器"
- "置信度评分 0-100"
- "90 分可直接使用"
- "假阳性率 < 5%"

#### 新定位（✅ 正确）
- **"AI 可用性审计工具"**
- **"不确定性和风险点标记系统"**
- **"辅助人工审计的编排器"**
- **"让专业人士判断'这份输出能不能进入下一步工作'"**

#### 核心洞察
**我们的工具做不到**：
- ❌ 判断事实真假（没有外部知识库）
- ❌ 逻辑推理（无法判断"8ft 的孩子"不合理）
- ❌ 常识判断（不知道 Monopoly Man 长什么样）
- ❌ 专业验证（不是数学家，看不出证明错误）

**我们的工具能做到**：
- ✅ 标记需要核实的内容（数字、日期、引用、专有名词）
- ✅ 检测多次运行的一致性（同一问题多次生成，对比差异）
- ✅ 提取原子主张（把长文本拆解成可验证的独立陈述）
- ✅ 追溯来源（如果用 RAG，标记每句话来自哪个文档）
- ✅ 辅助人工审计（提供结构化的审计界面，不是给结论）

### 3. MVP 功能设计

#### 目标用户
**科研机构用 AI 辅助整理文献的人**

#### 核心流程
```
用户上传文献 PDF
    ↓
用户输入研究问题
    ↓
系统调用 LLM 生成 3-5 次
    ↓
提取原子主张 → 对比一致性
    ↓
RAG 溯源 → 标记来源/无来源
    ↓
标记风险点 → 数字/日期/引用
    ↓
生成审计报告 → 人工核对界面
```

#### 界面设计
- ✅ 上传界面（拖拽 PDF）
- ✅ 问题输入（支持多次运行配置）
- ✅ 审计报告（一致性分析 + 来源追溯 + 风险点标记）
- ✅ 人工核对界面（逐条审核原子主张）

## ⚠️ 阻断性问题（用户审查发现）

### P0 级问题

1. **核心功能未接入产品**
   - `AuditReport` 和 `usabilityAudit` 虽然存在，但未被 `App.tsx` 或 `ObservePage.tsx` 使用
   - 没有任何用户路径能从上传 PDF 走到审计报告
   - 结论：只是孤立原型，不是可验收的 MVP

2. **文档管线无法实现页码溯源**
   - `ParsedDocument` 只有文件名和整段文本，PDF 解析已丢弃页边界
   - 最多截断到 6000 字符
   - 无法回答：这条主张来自哪一页？是否来自被截断的内容？

3. **一致性实验设计不成立**
   - 设计写的是"固定 seed，只改 temperature"，这测量的是温度变化，不是独立采样
   - `checkSelfConsistency()` 用 token 首次分叉判断，不同切分、同义表达都会误判
   - "完全一致 → 绿色"仍然暗示"可信"

4. **不确定性等级仍是未校准的综合评分**
   - 用硬编码规则生成"低/中/高"等级，只是把"90 分"换了个说法
   - 绿色勾号表示"低不确定性"，仍可能制造安全感

### P1 级问题

5. **数据收集不准确**
   - GPT-4 BS 只有 104 个 prompt，没有完整输出和真值标签
   - HaluEval 和 PRM800K 只是文档引用，没有原始数据
   - 无法用它验证召回率

6. **LLM 自己提取主张会形成闭环偏差**
   - 提取阶段可能漏掉、改写或新增内容
   - 后续审计只是在审计模型加工过的版本

7. **新代码验证覆盖不足**
   - 没有 `usabilityAudit.test.ts` 或 `AuditReport.test.tsx`
   - `text-safe-500` 样式类未定义

### 硬验收条件（下一阶段）

1. **端到端用户路径**：PDF → 生成 → 主张 → 来源 → 人工判定
2. **每条来源可追溯**：稳定回到文档页码、段落和原文摘录
3. **独立验证**：带人工标注的数据验证主张抽取、来源召回、一致性聚类

**详细分析**：[`docs/BLOCKING_ISSUES.md`](docs/BLOCKING_ISSUES.md)

## 💡 关键设计决策

### 1. 为什么不做"幻觉检测器"？
- 人发现幻觉靠的是：外部资料、逻辑检查、常识判断、专业知识
- 我们的工具没有这些能力
- 如果宣称能检测幻觉，是在误导用户

### 2. 为什么不给"置信度评分"？
- 评分暗示"90 分可以用，50 分不能用"
- 但低熵（看似高置信）可能是错的
- 高熵（看似低置信）可能是对的
- 评分会给用户错误的安全感

### 3. 为什么强调"辅助人工审计"？
- AI 不能判断真假
- 最终判断必须由人做出
- 工具的价值是：减少人工审计的工作量，提高效率

### 4. 为什么选"科研文献整理"作为第一个场景？
- 痛点明确：编造论文引用是最危险的幻觉类型
- 可验证性强：论文有 DOI、arXiv ID，容易核实
- 用户专业：科研人员有能力判断内容真假
- RAG 场景：上传文献 → 生成摘要 → 溯源到原文
