## 一、首屏（A1–A4）

```
【第一层 · 谜题】
为什么同一句问题，AI 每次回答都不一样？

【第二层 · 谜底】
因为这个答案，曾经差点变成另一个答案。

【第三层 · 证据切片】（真实数据，步 68/229）
    本身      20.08%
    ─────────────────
    这个词    20.08%
    ─────────────────
    其余所有候选合计 59.84%

    前两个候选的概率几乎完全相同。
    （P1 切片规则：必须同时展示其余候选合计，不制造「二选一」的错觉）

【按钮】
亲眼看这一刻 →
```

**按钮承诺/兑现两栏（P4 检验）**
- 承诺：看到那个差点分岔的瞬间。
- 兑现：点击后演示快进直达犹豫点暂停帧（≤10 秒内出现 20.08% vs 20.08% 的候选榜）。

**首屏不出现**：softmax / temperature / seed / top-p / WebGPU / 模型规格 / Observatory 结构。

## 二、演示暂停帧（A5，机制第一次出场）

演示停在犹豫点，底部固定引导卡文案：

```
停一下——它在这里差点走向另一个答案：
「本身」20.08% vs 「这个词」20.08%

AI 并不是先想好整句话。
它每写一个字，都在从几十个候选里按概率抽签。
同一个 seed，这枚硬币每次掷出同一面；
换一个，就可能是另一个答案——这就是你每次得到不同回答的原因。

（提示行）右侧候选榜每一行都可点，看看它差点选的字
（按钮）▶ 继续看它写完
```

术语首次出场顺序：概率 → 抽签/硬币 → seed → （展开后）温度、top-p。
候选榜展开处保留现有严谨口径：Top-8 · 全量 softmax 后截断记录 · P 为 P(vocab)。

## 三、演示收束语（A6，真实统计版）

```
这个回答共 229 步。
其中 15 步，前两名候选的概率差不足 5%——
它有 15 次差点变成另一个答案。

最险的一步：第 68 步，差距不到 0.01%。

（按钮 1）回看这 15 个瞬间
（按钮 2）跑自己的问题，看它掷你的硬币
```

**按钮承诺/兑现两栏（P4 检验）**
- 按钮 1 承诺：逐个看到 15 个差点分岔的位置；兑现：装载该 trace 并按差距排序跳转。
  ⚠ 该跳转列表为新功能，列入批次 1 交付物（锚点 A6）；未实现前按 P4 不得上线此按钮。
- 按钮 2 承诺：用户自己的问题也会产生同样的可观察记录；兑现：聚焦提示词控制台（模型加载仍由用户显式选择）。
- 谜题闭环补丁（评审 R2）：收束层附一行出口「同一句问题，换个 seed 再跑一次，并排看两个答案」，复用已有 CompareView；这才真正兑现首屏谜题句「每次回答都不一样」的证明。

**运行时计算口径**：`close = topk[0].prob − topk[1].prob < 0.05 且 topk[0].prob > 0.05` 的步数；
全部数字（含首屏切片）实时从当前 demo trace 计算，禁止硬编码；更换 demo trace 时文案零成本自适应（锚点 A10）。

## 四、Evidence First 自查（发布前）

1. 「差点变成另一个答案」→ 由切片 20.08/20.08 + Branch 能力支撑；不写「答案会完全不同」（C3 未上线前措辞收敛）。
2. 「按概率抽签」→ 由采样管线展示（softmax → T → top-p → RNG(seed) → selected）支撑。
3. 「15 次 / 229 步 / 0.01%」→ 每个数字可点开对应步的 top-k 原始记录。
4. 无拟人陈述句：「犹豫点」仅作为位置索引名出现。
