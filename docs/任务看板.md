## 💭 未来规划 / 待评估

### AI 3D 数字人/数字宠物方案调研 (2026-08-05)

**背景：**
用户希望通过 AI 助手/伴侣让普通用户更容易理解和使用 AI。调研了 GitHub 上成熟的开源方案。

**调研发现：**

#### 可用的开源方案
1. **ProtoReplicant** - 完整链路（VAD→STT→LLM→TTS→VRM），浏览器原生
2. **three.ws** - GLB/glTF + LLM + 记忆 + 情感系统，Three.js 原生
3. **Live2D 方案** - 轻量级 2D 角色（5-10 MB），二次元风格
4. **TeachAny** - 教育方向，分步引导式交互

#### 用户需求明确化
- **不只是动画**：需要真正能对话的 AI 伴侣
- **有记忆**：记住用户的使用习惯和问题
- **场景感知**：理解当前用户在做什么（加载模型/查看思考链/调参数等）
- **知识库集成**：后期会搭建知识库、用户记忆系统
- **双重定位**：
  - 主对话 = 实验对象（被观测的 AI）
  - 伴侣 AI = 研究伙伴（帮助用户理解观测结果）

#### 设计方向讨论
- **为什么需要"陪伴"**：开发/使用过程孤独，等待时需要情感反馈
- **参考案例**：Claude Code 的狗狗 Bit（不是功能性，是情感缓冲）
- **形态选择**：
  - ❌ 3D 人形：不符合项目 Cognitive DNA（"不做拟人动画"）
  - ✅ 观测助手：呼应 "AI Observatory" 主题
  - 可选：Emoji 助手 / SVG 机器人 / Live2D 观测员

#### 技术实现考虑
- 双 Worker 架构：主对话 Worker + 伴侣 AI Worker
- 上下文感知：伴侣能看到当前页面状态（在哪个页面、看什么数据）
- 记忆系统：localStorage + 后期云端同步
- 知识库：项目文档 + AI 概念解释库
- 语音交互：可选的语音输入/输出

#### 优先级建议
- **立即做**：首屏引导提示（OnboardingPrompts 组件已创建）
- **本周做**：AI 知识导航地图
- **下周做**：语音输入（Web Speech API）
- **1 个月后**：评估是否需要 Live2D 观测员
- **3 个月后**：如果数据支持，实现完整的 AI 伴侣系统（对话 + 记忆 + 知识库）

#### 技术债务评估
- 3D 数字人：3-4 周开发，30-50 MB 资源，高复杂度
- Live2D 伴侣：3-5 天开发，5-10 MB 资源，中等复杂度
- AI 对话伴侣：1-2 周开发（双 Worker + 上下文感知 + 记忆），低资源消耗

**决策：** 等所有当前任务完成后再推进。优先完成核心功能稳定性和用户引导优化。
