## T0 · Spike：首屏深色化决策（≤半天，产出是决策不是代码）

- 盘点 `LandingHero.tsx` 现有浅色视觉资产（渐变、插画、卡片样式）改深色的工作量。
- 两个可选结论：①全深色（首屏→观察页零割裂，推荐）；②首屏保持浅色但过渡段做渐变衔接。
- 超过 1 天工作量则选②并记录到未决问题。**Spike 结论写进本文档修订，不闷头做。**

## T1 · 构建期数据管道（A10）

**目标**：首屏切片与全部统计数字来自真实 trace 文件、构建时提取、运行时零网络依赖。

- 新增 `scripts/extract-demo-stats.ts`（挂入 build/dev 前置）：
  读 `src/assets/demo.aitrace.json` → 产出 `src/lib/demoStats.generated.ts`：
  ```ts
  export const DEMO_STATS = {
    totalSteps: 229,
    closeSteps: [...],        // {index, gapPct, a:{text,prob}, b:{text,prob}, restMass} 按 gap 升序
    tightest: {...},          // 步 68：本身 20.08 / 这个词 20.08 / rest 59.84
    prompt, modelId, params,  // seed 473055871 / T 0.7 / top-p 0.95
  }
  ```
- 口径固定：`close = topk[0].prob − topk[1].prob < 0.05 && topk[0].prob > 0.05`；
  `restMass = 1 − (top1+top2)`（含 top3–8 与尾部，注释写明）。
- 生成文件进仓库（构建可重现），脚本幂等；换 demo trace 只需重跑脚本。
- **测试**：脚本单测（给定小型 fixture trace 校验各字段）；生成值与 SamplingInspector 展示口径一致性断言。

## T2 · 犹豫点切片组件（A3）

**新组件** `src/components/HesitationSlice.tsx`（首屏与暂停帧复用同一视觉，推演层"认出来"要求）：

- 三根横条：两根等长强调色条（token 文本在左、百分比在右）+ 一根灰条「其余所有候选合计 59.84%」。
- 高度合计 ≤120px；唯一动效：两根等长条 0→20.08% 入场 600ms ease-out（首屏唯一动效预算）。
- 点击/tap 展开原始 top-8 + 采样参数（复用 SamplingInspector 行样式，不新造视觉语言）——
  这是 C2「陈述可展开」组件的第一个实例，P1 检验入口。
- 右下低调「查看原始数据」链接（U3 入口，通向 trace 视图）。
- **测试**：渲染三行、rest 行必现（P1 切片规则）、展开内容与 DEMO_STATS 一致。

## T3 · 首屏改版（A1/A2/A4/A7）

改 `LandingHero.tsx`：

- 四段纵排、最大宽 680px：谜题句（桌面 clamp(28px,4vw,40px)/手机 24px）→ 谜底句（退一级）
  → HesitationSlice → 主按钮「亲眼看这一刻 →」（min-height 44px）。
- 文案严格按 `首屏文案稿.md` 第一节；首屏第一层禁词自查：softmax/温度/seed/top-p/WebGPU/模型规格。
- 现有技术卡片（模型/WebGPU/本地）整体下移第二屏（A7），不删内容只降层级。
- 移动端：四段在 100vh 内完整可见（iPhone SE 668px 下限）；3D 不进首屏关键路径
  （维持 lazy；手机演示走 SamplingChamber 2D fallback）。
- **验收（推演失败判据）**：慢速 3G 模拟下首屏文字 <2s 可读；Three.js/ONNX 不出现在首屏 chunk。

## T4 · 演示快进急停（A4 实现修正版）

改 `ObservePage.tsx` `startDemo`：

- 新增入口参数 `fastArrive`（首屏按钮触发）：前段快进（3–4 秒内扫过 pauseAt 之前的步，
  tick 间隔压缩），到犹豫点**急停**——"快"是铺垫，"停"有重量（推演对 A4 的节奏修正，
  不完全跳过前段）。
- 总时长控制：点击→暂停帧 ≤10 秒（P4）；资源未就绪时 BreathingWait 式真实等待说明（评审 V4）。
- 保留现有完整节奏播放入口（观察页内「观看一次采样」不受影响）。
- **测试**：fastArrive 模式下暂停帧出现时间断言；pauseAt 定位与 DEMO_STATS.tightest.index 一致。

## T5 · 暂停帧解释层（A5）

- 引导卡内嵌 HesitationSlice 同款样式的两行候选（与首屏视觉呼应）。
- **测试**：paused 态文案与按钮可见性（沿用现有 LivePanel/ObservePage 测试模式）。

## T6 · 收束统计卡 + 15 瞬间列表 + 换 seed 出口（A6）

改 done 态固定卡 + 新增跳转列表：

- 收束文案真实统计版（数字来自当前播放 trace 实时计算，demo 用 DEMO_STATS）：
  「共 229 步 · 15 步差距不足 5% · 最险第 68 步差距 <0.01%」。
- **新功能**「回看这 15 个瞬间」：装载 demo trace 后按 gap 升序的步列表
  （每行：步号 · A vs B · 差距），点击 `jumpToToken(index)`；列表数据即 DEMO_STATS.closeSteps。
- 「换个 seed 再跑一次并排看两个答案」出口：有已加载模型 → 同 prompt 换 seed 跑一次并进
  CompareView；无模型 → 引导至模型选择（保持显式加载原则，绝不自动下载）。
- 每个数字可点开对应步（P1）；未实现跳转列表前该按钮不上线（评审 R3——本批次内实现，故上线）。
- **测试**：closeSteps 排序与跳转、无模型时出口降级行为。

# 批次 2 · Evidence First 界面化 + 旅程收敛（C1–C2 + 推演补充项）

1. **C2「陈述可展开」组件化**：`<EvidencedClaim focus={TraceFocus}>`——细虚线下划线 + ⌄，

   粒度纪律：每屏 ≤3 处，只给统计/比较/机制断言（推演"粒度陷阱"）。

   拟人陈述句降级为索引名；产出审查表（句子 → 处理：保留/改写/删除/组件化）。
3. **旅程收敛（推演第 2 层）**：生成完成后收束卡只保留唯一主出口
   （「这个回答有 N 个犹豫点，看最险的一个」），分岔树/方向按钮/导出/分享降为次级链接。
4. **等待时教学（推演补充）**：BreathingWait 期间展示标注版 demo trace 真图

# 批次 3 · 犹豫点双结局 + 行为 Benchmark 起步（C3 + D3/D4 首期）

依赖：批次 2 的 EvidencedClaim（双结局结论句用它呈现）+ 用户已加载模型的真实推理。

1. **C3 双结局**：暂停帧/收束卡入口「看两个结局」→ 从犹豫点对 top-2 候选各真实续跑
   （复用 BranchTree 续跑 + DualTraceChannel 布局）：顶部共享分岔切片，双栏逐 token 对齐，
   首个不同 token 高亮。**三种结果全接住**：不同（主故事）/殊途同归（预置文案
   「N 步后重新汇合——用词会抖动，观点常常稳定」）/跑崩（如实展示数值异常）。
   禁止只挑蝴蝶效应案例做默认演示（P1）。
2. **D3 行为 Benchmark 首期**：定位为"自己和自己比"的回归工具——同 prompt 多 seed 重复跑，
   分数模型定死为分布不是单值：`{seeds[], values[], median, range}`；首个指标用现有规则命中率。
3. **D4 规则包 V1**：现有 `rules.ts` 结构的 JSON 导出/导入 + 命名 + 版本号，**零新 DSL**
   （推演"DSL 野心"防线）；DSL 等真实用法沉淀后再议。
4. 验收：双结局三分支各有测试 fixture；多 seed 分数的中位数/极差展示；四项自查。
