# 批次 4 验收记录 · 官方引用层 + 系统基准口径

> 对应锚点：D1（官方能力引用层）、D2（系统 Benchmark 扩展）。
> 验收方式：tsc / oxlint / vitest（186 通过，+14）/ build + 云端页面走查 + 组件渲染测试（无录屏截图）。

## D1 · 官方公开成绩引用层

- `src/lib/officialBench.ts`：引用条目结构强制带 upstream（成绩属于上游原模型）、
  sourceLabel、sourceUrl（可点核验）、verifiedAt（逐条核实日期）。
- **宁缺毋假**：只录入我打开来源页逐条核对过的数字——
  - DeepSeek-R1-Distill-Qwen-1.5B（官方模型卡评测表）：AIME 2024 pass@1 28.9 /
    cons@64 52.7、MATH-500 83.9、GPQA Diamond 33.8、LiveCodeBench 16.9、CodeForces 954。
  - Phi-3.5-mini（官方模型卡评测表）：MMLU 5-shot 69、MMLU-Pro 47.4、
    GSM8K 86.2、HumanEval 62.8。
  - 其余 6 个模型如实显示「尚未录入」空态，不编数、不外推。
- **混层生死线**（推演文档）：官方引用卡用琥珀色 + 「引用 · 非本机实测」角标，
  与本机实测（Live Benchmark 加「本机实测」绿色角标）永远不同表不同色；
  卡内注明量化镜像可能影响成绩。
- 单测：来源字段完备性、modelId 必须对应注册表真实条目（防悬空引用）、
  分数必须带基准名与计分口径；组件测试验证引用表与空态两种渲染。

## D2 · 系统基准口径扩展

- `src/lib/latencyStats.ts`：
  - `latencyStats`：逐 token 延迟 p50/p95（线性插值分位数），样本 <8 返回 null 不硬算；
    展示时注明不含首词（首词另含提示预处理，口径不同）。
  - `decaySummary`：上下文衰减多点采样——四等分窗口平均吞吐 + 首末窗口减速比，
    每个点都是一段真实生成的均值，不是拟合曲线；样本 <32 返回 null。
- Device 页 Live Benchmark 完成态增加 p50/p95 行；Context Decay 完成态改用
  decaySummary 的四个采样点（与曲线并列展示），口径文案同步更新。
- VRAM 不测：浏览器无法获得显存占用，按「探测不到就如实标注」原则不显示估算值。
- 单测：分位数边界、无效 dt 过滤、匀速/衰减序列、窗口标签覆盖完整序列。
