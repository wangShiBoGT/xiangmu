# AOKS · Source of Truth（权威层级与裁决）

> 本文只回答：当文件、想法或任务冲突时，**谁有最终决定权**。

## 权威顺序

1. **四卷宪法**：`docs/E5-VolumeI~IV`。Vol I 的基本法、产品语法与词表优先于一切产品偏好。
2. **AODL**：`docs/AODL/`。在不冲突于四卷前提下，定义认知与视觉 DNA。
3. **已批准的模块体验稿与实施规划**：`Design/Future/`、`docs/E5-双轨开发计划.md`、`docs/直通E5完整规划.md`。它们定义模块范围，不得改写上层原则。
4. **实时执行状态**：`docs/任务看板.md`。它定义现在做什么，不能覆盖上层。
5. **历史证据**：验收、评审、早期推演、旧计划。用于解释过去，不自动决定未来。

同层冲突：优先选择更具体、更新日期更晚、且有验收或设计决策卡佐证的版本；仍无法裁决时，创建决策记录而非凭感觉修改多个文件。

## 角色边界

| 类型 | 可以做什么 | 不可以做什么 |
|---|---|---|
| Canonical | 定义规则与术语 | 被任务看板或体验稿悄悄改写 |
| Digest | 供日常快速执行 | 增加与事实源不同的新规则 |
| Plan | 定义已批准的未来范围 | 声称已实现或绕过五闸 |
| State | 记录当前完成与下一步 | 充当长期产品哲学 |
| Archive | 提供可追溯历史 | 进入默认上下文或覆盖新决策 |

## 修改协议

- 改**原则/词表/产品语法**：先改 Canonical，再检查 Digest 与路由是否需要更新。
- 改**已批准模块方案**：改对应体验稿与任务看板；若触及原则，按上条处理。
- 改**执行状态**：只改任务看板；不要反写历史。
- 改**历史记录**：只允许更正事实性错误并明确更正原因，不重写当时结论。

## 本项目的特别裁决

“好看”“有生命感”“更酷”不能压过 Evidence First。没有对应 trace/测量的状态、关系、动画或空间隐喻，一律不作为产品事实呈现。视觉的权利来自它增加了可验证的理解，不来自它更像 AI。
