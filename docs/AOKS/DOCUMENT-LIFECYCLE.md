# AOKS · Document Lifecycle（文档生命周期）

> 本文只回答：一份文档创建后该如何活下去。目标是保留项目记忆，同时不让旧材料污染当前开发。

## 五种状态

| 状态 | 用途 | 默认加载 | 更新规则 |
|---|---|---|---|
| Canonical | 唯一原则、规范或口径 | 按路由回卷 | 改动需检查所有 Digest/Pointer |
| Digest | 高频速查 | Kernel 时 | 不新增原则，只压缩并指向住址 |
| Plan | 已批准的未来方案 | 对应任务时 | 实现后更新状态并保留设计依据 |
| State | 实时任务与风险 | 接续任务时 | 每次任务完成当场更新 |
| Archive | 验收、评审、推演 | 不自动加载 | 不删除；只修正明确事实错误 |

## 新建文件前的检查

只有在现有 Canonical/Plan/State 无法回答一个独立问题时才新建。新文件顶部必须写明：

```md
> 角色：Canonical / Digest / Plan / State / Archive
> 只回答：<一个问题>
> 规范住址：<若不是 Canonical，写 See 路径>
> 何时加载：<任务类型>
```

预计超过约 500 行，或开始回答第二个问题时，拆分并在原文件加指针。

## 生命周期迁移

```text
探索想法 → Plan（体验稿） → 通过五闸 → 实现 + State 更新
                                     ↓
                              方案被替代 → Archive（保留原因）
```

体验稿不是代码待办：没有真实数据来源、认知定位和失败判据的想法仍停留在讨论，不进入 `Design/Future/`。

## 保存规则

- 保留所有既有验收、评审、推演和完成批次文件；它们是可追溯的产品记忆。
- 不为“目录好看”移动已有主文档。优先使用角色地图与路由，避免打断仓库、代码和外部链接。
- 真正需要物理迁移时，先建立迁移表、保留原路径的说明文件，并在一次独立变更中完成。
