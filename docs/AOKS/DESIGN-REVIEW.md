# AOKS · Design Review（多角色设计审查）

> 本文只回答：在提交前，怎样用不同视角攻击一个方案，留下真正帮助理解的视觉。

## 四个必问角色

| 角色 | 反问 | 不通过的典型信号 |
|---|---|---|
| Explorer | 我三秒内知道现在发生什么、可以点哪里、会得到什么吗？ | 首屏是术语、表格或多个竞争焦点 |
| AI 研究者 | 每个陈述、数值、连接与状态能回到哪条 trace/测量？ | 熵被写成心理状态；缺数据却有关系/动画 |
| 产品负责人 | 这一步推进了 Question→Evidence→Interaction→Conclusion→Replay 的哪一环？ | 只增加一个面板或酷效果，没有下一次好奇 |
| 视觉/交互负责人 | 静态时仍有清晰层级吗？运动解释了时间、因果、空间或注意吗？ | 赛博模板感、装饰粒子、默认动个不停 |

## 审查顺序

1. **静态第一屏**：遮住动效后，唯一主焦点、主动作、当前证据仍清楚吗？
2. **数据映射**：颜色、大小、位置、连线和动效是否各自有一个可说出的数据语义？
3. **点击兑现**：每个可点对象承诺什么，十秒内怎样兑现？是否引向下一层而非死胡同？
4. **诚实缺席**：数据缺失时是否明确为空态，而不是用中性占位“假装观察到”？
5. **专业下潜**：token_id、seed、softmax 等是否被放入正确层级，而没有挡住 Explorer？

## 结论格式

每次审查输出三项即可：

```text
保留：哪一项因真实数据映射而提高理解。
修改：哪一项阻碍焦点、证据或探索。
删除：哪一项删掉后用户不损失信息。
```

若无法写出“保留”的数据映射，默认删除该效果。
