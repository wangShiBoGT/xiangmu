# 亲和层改版：首页 + 档案（2026-07-24 创始人定调 · 规划）

> 创始人原话锚点：「我要的不仅是专业的人 还有普通用户也可以深入了解运作整个 AI」「首页我还是看不懂 AI」「档案部分可以（做成常规卡片布局 点进去打开一个相关对话）因为一进去一个图不知道是做什么的」。
> 方向一句话：在既有专业层之上补一层**亲和层**——普通人打开首页 10 秒内能说出「AI 在干什么」，打开档案先看到熟悉的「对话」，专业镜头永远是下一层（不删专业能力，只调整入口顺序）。
> 共同宪法不变：所有画面对应真实 trace；无数据诚实缺席；三级下潜；不整页重造能复用的组件。

## 诊断（为什么现在看不懂）

- 首页（WorkspacePage）是工程控制台四格：Current Run / Performance / Activity / Trace，标题是英文、读数是 seed / tok/s / trace completeness——对普通人是「一堆仪表」，没有回答「这是什么、我能干嘛、AI 到底在干什么」。
- 档案（ArchivePage）进去先是图谱 + Run Inspector 核验面板——「一进去一个图不知道是做什么的」。运行的「内容」（问了什么、答了什么）反而要下钻才能看到。
- 已有的人话组件（此刻卡 / 思考字幕 / 故事章节 / 检索决策卡）都埋在显微镜层，首页没有借力。

## 外部调研（2026-07-24 · 创始人要求「去看外面的讨论和案例」后补）

**看了什么**：HN 上 Anthropic《Tracing the thoughts of an LLM》两条大讨论串、r/LocalLLaMA 生态、三个同类工具（Columbia TokenProbe / llm-xray / gekro Token Probability Visualizer）、三个 vibe-coding 平台（bolt.new / v0 / websim）的上手流程与社区文化。

**结论一：大众对「看 AI 怎么想」有真实的巨大兴趣，但对拟人化包装强烈过敏。**
Anthropic 那篇之所以病毒式传播，靠的是「一个简单叙事 + 一个惊人实例」（如「它写诗时提前几个词就规划了押韵」）；同一串里最高赞的批评全是打「thinking/mind 是营销话术」。→ 我们的 Evidence First 红线是对的，且是差异化卖点：**别人讲故事没证据，我们每句话都能点开看原始记录**。文案继续用「选择/犹豫/概率」，不用「思想/意识」。

**结论二：同类工具已验证的「普通人秒懂」画面高度一致——答案正文本身按把握度着色。**
gekro：绿=很有把握(>85%)、红=在猜(<15%)，悬停看候选词；llm-xray：回答每个 token 下划线粗细=把握度，「点任一 token，全部视图倒回那个决策瞬间」，且**每次运行产出一张可分享的卡片**；TokenProbe：零门槛「输入问题→逐词看候选」。→ 首页 hero 不该是导览图，而应是**一段被着色的真实回答本身**；分享卡（本项目已有 shareCard 库）应提升为一级出口。

**结论三：vibe-coding 平台的零门槛公式 = 现成示例一键跑 + 「你不需要懂细节」的语气 + 秒出结果 + 可分享/可 remix。**
bolt 的 Quickstart 直接给一条可粘贴的完整 prompt；websim 的文化是「你想到，你就能做出来」+ 发布/点赞/remix。→ 首页要有**预置示例问题 chips（点一下就跑/就播演示）**，而不是空输入框等用户想问题。

**由调研修订的规划**（下方 C/D 已按此更新）：C1 的 hero 从「三格导览」改为「着色答案 + 一句图例」；新增 C6 示例问题 chips；新增 C7 分享卡一级出口；D1 卡片摘录同样用把握度着色。

## Sprint C · 首页「10 秒看懂 AI」

**验收判据（唯一）**：不懂 AI 的人打开首页 10 秒，能用自己的话说出「AI 回答问题时要一步步做选择，这个工具把每一步都录下来了，我能回放」。

- C1 首屏 hero（调研修订）：**一段按把握度着色的真实回答本身**——用预录演示 trace（或上次运行）的正文，逐词按真实 prob 着色（绿=很有把握，琥珀/红=在猜），配一句图例「颜色 = 它写这个词时有多大把握；点任一词看它当时的候选」；点词就地弹出该步真实 top-k 迷你条，再点进显微镜定位该步。下方一行小字三步句：「它每写一个字都在候选里选一次 · 每次选择都被录了下来 · 你可以回放它」+「▶ 看它思考一次（30 秒）」大按钮（复用既有 demo Replay，零下载零模型）。
- C2 「它刚才做了什么」卡（有存档时）：用 `storyChapters` 把上次运行拼成一句故事概要（如「启动 1.2s → 想了 96 步 → 在第 41 步犹豫过 → 用 133 步写完回答」，数字全实测），点击直接打开该记录的 Story Mode。取代现 Activity 卡的首屏位置（Activity 下移）。
- C3 术语人话化（全站字典，一处定义多处复用 `lib/plainWords.ts`）：seed→「随机种子·同种子可复现」、tok/s→「生成速度」、Trace→「运行档案」、entropy→「犹豫程度」、top-k→「候选词」；专业术语保留在括号/tooltip，不删除。
- C4 空状态（无存档、无模型）：两个大动作卡「先看一段演示（不用下载模型）」/「加载一个小模型试试」，不再是四格空壳。
- C6（调研新增）示例问题 chips：输入框下 3–4 个现成问题（如「为什么天空是蓝色的？」），点一下就跑（有模型）或就播对应演示（无模型）——bolt Quickstart 公式，不让空输入框劈用户。
- C7（调研新增）分享卡一级出口：把既有 `lib/shareCard` 的导出入口提到完成态与档案对话页的一级动作（llm-xray 验证：每次运行产出一张可分享卡片是传播入口）。
- C5 验收：C 组件全部消费真实数据（演示 trace / 上次运行 trace）；遮住输入框页面依然成立（导览+演示+故事概要均可用）；验证序列全绿。

## Sprint D · 档案卡片化 + 对话式档案页

**验收判据**：进入档案第一眼是「一张张看得懂的卡片」；点进任一张先看到「一段对话」；图谱与核验面板变成下一层。

- D1 档案首屏改常规卡片网格（2–3 列自适应）：每张卡 =
  问题一行（加粗）+ 回答摘录两行（strip thinking 后的正文前 80 字，按把握度着色——与 C1 hero 同一视觉语言）+ 人话徽章行（模型名 / 日期 / N 个词 / 生成速度）+ 底部迷你 token 色条（复用既有色条，一眼看出「这次它犹豫多不多」）。星标/删除保留在卡片角落。
- D2 点卡片打开「档案对话页」（新组件 RunStoryPage，路由仍在档案层内）：
  - 上半部：像聊天记录——用户问题气泡 + AI 回答气泡（正文，thinking 折叠为「它先想了 N 步 ▸」可展开）；
  - 下半部：一排动作卡「▶ 讲成故事 / 回放这次运行 / 放进显微镜 / 与另一次对比 / 导出 .aitrace」——每张动作卡配一句人话说明它能看到什么；
  - 原图谱 + Run Inspector 整体收进「专业视图」折叠区（不删除，默认收起）。
- D3 卡片列表支持按模型筛选与文字搜索（现有数据结构支持则做，不新增索引设施）。
- D4 验收：回答摘录与 trace steps 原文一致；动作卡全部接到既有真实能力（Story Mode / Replay / 显微镜 / CompareView / 导出）；验证序列全绿。

## Sprint E（讨论稿）· 理解层：「AI 是怎么运行的」一条连贯旅程

> 创始人 2026-07-24 追加：「3D 柱子最下面附近搞一堆词、AI 关联上它」「还要能够关联上，不是我说一个想法你就一个解法」「我还是不太理解 AI 是怎么运行的」。
> 二次调研补充：Transformer Explainer（Georgia Tech，49 万用户、90 人对照实验、CHI 2026）验证的公式 = **一张总览图上的真实数据流 + 按需逐级展开细节 + 用户自己的输入现场跑**；3Blue1Brown 的叙事骨架 = 「每个词的含义被上下文逐步改写」；transformers.js 有 `getAttentions()` API，注意力可视化的堵点只在模型导出（Transformer Explainer 证明浏览器内 GPT-2 可带注意力运行——存在解法：为「理解层」单独配一个带注意力导出的小演示模型，主聊天模型不受影响）。

**核心思路：不再给一堆独立镜头，而是把同一次真实运行讲成一条四幕连贯旅程，幕与幕之间视觉上「接力」同一个词：**

- 第一幕「它在读你的问题」——你的问题一行字，AI 写当前词时「盯着」哪几个词发光（注意力连线，即创始人概念图《它在看哪里》）；
- 第二幕「它想到了一堆词」——被盯住的词引出候选词堆（3D 概率场柱底直接摆候选词原文，柱高=概率——创始人的柱底词想法在这里落位，且与第一幕的连线相连）；
- 第三幕「它选了一个」——选中词落进答案，按把握度着色（与首页 hero 同一视觉语言）；
- 第四幕「这样重复了 N 次」——答案整段着色浮现，接 Story Mode / Replay。

**数据可行性分级（Evidence First）**：第二/三/四幕数据现成（top-k/prob/steps 全在 trace 里）；第一幕需要注意力——**已于 2026-07-25 云端实测验证可行**：用 torch.onnx（dynamo, opset 18）把 distilgpt2（英文）与 uer/gpt2-distil-chinese-cluecorpussmall（中文，同 GPT-2 架构、同一导出脚本）导出为带 `logits + attn.0..5` 输出的 ONNX，onnxruntime 实测注意力行和=1、变长输入 OK、中文 top-5 候选合理。体积 fp32 约 330MB/模型，发布前做 int8 量化（预期 ~80MB 级）。产品层做「中文演示 / English demo」双语切换，用户自选。主模型 trace 无注意力时第一幕诚实缺席、从第二幕开始。

**入口**：首页「▶ 看它思考一次（30 秒）」直接进这条旅程（取代单纯 demo replay）；旅程结束落到「用你自己的问题再来一次」。

**status: v1 已交付（2026-07-25）**——四幕旅程 `JourneyPage` 上线：中/英双演示切换，数据为理解层演示模型离线实测（`src/assets/journey.zh/en.json`），页内明确标注不冒充主聊天模型。后续升级「现场跑用户自己的问题」需部署带注意力的量化 ONNX（~80MB/语言，导出脚本 `tools/export_attention_onnx.py` 已实测跑通），待创始人确认下载体积成本后再排。

不动：显微镜层、Story Mode/Compare 本体、trace 格式、worker。

## 五闸自检

- 六层栈：亲和层是 renderer 与文案层，证据层不变。
- Evidence First：导览迷你图/故事概要/卡片色条全部实数据；演示按钮用预录真实 trace。
- 认知阶梯：亲和层就是 Explorer 的第 0 阶，向下钩子 = 动作卡与「专业视图」折叠区。
- Q→E→I→C→R：「AI 到底在干什么？」→ 真实一步的候选/色条 → 看演示/点卡片 → 用户自己说出结论 → Story/Replay 可复放。
