## 概述

**WebGPU LLM Observe** 是世界领先的 AI 置信度审计工具，通过多维度幻觉检测技术，帮助您评估 AI 生成内容的可信度。

**核心特点**：
- ✅ **完全透明**：所有检测方法公开，每个判断都有学术论文支撑
- ✅ **多维度检测**：5 个独立维度交叉验证，不只看熵值
- ✅ **零成本**：浏览器本地运行，无需付费 API
- ✅ **可复现**：相同输入永远产生相同结果
- ✅ **可引用**：开源 + 方法论公开，适合学术使用

## 检测维度

### 维度 1：Token-level 熵值异常

**原理**：
熵（Entropy）衡量模型生成某个 token 时的"不确定性"。熵值越高，模型越"犹豫"。

**公式**：
```
H = -Σ p_i * log(p_i)

其中 p_i 是第 i 个候选 token 的概率
```

**检测内容**：
- **高熵 token**：熵值 > 3.0（琥珀色）或 > 4.0（红色）
- **熵值突变**：相邻 token 熵值差 > 2.0，表示生成方向突然分叉

**学术依据**：
- Shannon Entropy 理论（信息论基础）
- 经验阈值基于 WebGPU LLM 实测数据

**局限性**：
- 熵值高不一定是幻觉，可能是合理的创意发散
- 熵值低也不保证正确，模型可能"过度自信"

**示例**：
```
"天空是蓝色的" → 熵值 1.2（低不确定性，常识问题）
"2023年中国GDP约为18.5万亿美元" → 数字部分熵值 0.8（模型很确信，但可能是错的）
```

---

### 维度 2：时间序列异常

**原理**：
将 token 概率序列看作时间序列，幻觉常表现为：
- 概率突然下降
- 长期处于低概率区域
- 高波动率（忽高忽低）

**检测内容**：
1. **概率突降**：相邻 token 概率差 > 0.3（30%）
2. **低概率区域**：连续 5+ tokens 概率 < 0.3
3. **高波动率**：标准差 > 0.25

**学术依据**：
- HALT 论文（ArXiv 2602.02888）
- "Hallucination Assessment via Log-probs as Time series"

**示例**：
```
Token 序列概率：
[0.9, 0.85, 0.88, 0.25, 0.22, 0.28, 0.90]
           ↑ 这里概率突降 0.63
        ↑───────────↑ 这段是低概率区域
```

---

### 维度 3：事实性风险标记

**原理**：
LLM 容易在具体事实上幻觉（编造数字、虚假引用、错误日期）。我们不判断真假，而是**标记需要核实的内容**。

**检测内容**：
1. **具体数字** + 低熵（< 1.5）：模型很确信但可能错
   - 示例：GDP、人口、距离、百分比
2. **日期**：模型的时间知识可能过时
   - 示例：2023年、8月6日、2022-01-01
3. **引用标记**：模型经常编造不存在的论文
   - 示例：[1]、et al.、DOI:、arXiv:

**学术依据**：
- OpenAI 最佳实践："标记需要验证的内容"
- 经验观察：LLM 幻觉常发生在具体事实

**重要提示**：
这个维度不是说"检测到的都是错的"，而是"这些地方容易出错，建议人工核实"。

**示例**：
```
❌ 高风险："根据 Smith et al. (2021) 的研究 [1]，全球变暖速度是 2.3°C/decade"
   → 论文可能不存在，数字可能编造

✅ 低风险："天空看起来是蓝色的"
   → 不涉及具体数字或引用
```

---

### 维度 4：自洽性（Self-Consistency）

**原理**：
同一问题多次生成，如果答案高度一致 → 可信；如果答案分散 → 不可信。

**计算方法**：
```
一致性评分 = 1 - (分叉次数 / (运行次数 - 1))

示例：
- 10 次运行，8 次答案相同 → 一致性 80%
- 10 次运行，每次都不同 → 一致性 0%
```

**学术依据**：
- Wang et al. (2022) "Self-Consistency Improves Chain of Thought Reasoning"
- OpenAI Cookbook 推荐实践

**使用方法**：
运行同一 prompt 3-10 次（建议 5 次），系统自动计算一致性评分。

**局限性**：
- 需要多次运行，计算成本较高
- 只能检测"答案不一致"，不能证明"一致的答案就是对的"

**示例**：
```
Prompt: "用一句话解释为什么天空是蓝色的"

运行 1: "因为大气散射蓝光"
运行 2: "因为大气散射蓝光"
运行 3: "因为大气散射短波长光"
运行 4: "因为大气散射蓝光"
运行 5: "因为大气分子散射阳光中的蓝色波段"

→ 语义高度一致，自洽性评分 > 80%
```

---

### 维度 5：语义多样性（简化版）

**原理**：
多次运行的答案如果**用词完全不同但语义相同** → 高度一致；如果**语义也不同** → 模型不确定。

**计算方法**（简化版）：
```
1. 提取每次运行的 3-gram（三连词）
2. 计算 Jaccard 相似度（重叠率）
3. 多样性 = 1 - 平均重叠率
```

**阈值**：
- 多样性 < 0.3：高度一致（可信）
- 多样性 0.3-0.7：正常范围
- 多样性 > 0.7：高度分散（警惕）

**学术依据**：
- Farquhar et al. (2024) Semantic Entropy（简化版）
- Jaccard Similarity for text diversity

**完整版（未来）**：
使用 NLI（自然语言推理）模型判断语义等价，更准确但成本更高。

## 置信度评分

基于 5 个维度，计算综合置信度评分（0-100）：

### 单次运行（无自洽性数据）

```
评分 = 40% × 熵值评分 + 30% × 时间序列评分 + 30% × 事实性评分

其中：
- 熵值评分 = 100 × (1 - min(平均熵 / 5, 1))
- 时间序列评分 = 100 × (1 - 异常数量 / Token 总数 × 10)
- 事实性评分 = 100 × (1 - 风险标记数量 / Token 总数 × 5)
```

### 多次运行（有自洽性数据）

```
评分 = 30% × 熵值评分 + 20% × 时间序列评分 + 20% × 事实性评分 + 30% × 自洽性评分

其中：
- 自洽性评分 = 一致性率 × 100
```

### 评分解读

| 分数 | 等级 | 建议 |
|------|------|------|
| 90-100 | 高置信度 | 可直接使用，但仍建议核实关键数字和引用 |
| 70-89 | 中等置信度 | 部分内容需核实，特别是标记的风险点 |
| 50-69 | 低置信度 | 建议人工全面审查 |
| 0-49 | 极低置信度 | 不建议使用，模型高度不确定 |

**重要提示**：
- 高分不代表 100% 正确，只是"模型相对确信"
- 低分不代表完全错误，可能只是"模型不确定"
- 关键决策场景（医疗、法律、金融）请务必人工复核

## 假阳性率和召回率

### 目标

- **假阳性率** < 5%：不会误报太多正常内容
- **召回率** > 80%：能捕获 80% 以上的真实幻觉

### 验证方法

我们在以下数据集上验证：
1. **HaluEval**：学术标注的幻觉数据集
2. **TruthfulQA**：测试模型是否模仿人类错误观念
3. **自建案例**：从真实使用中收集的幻觉案例

### 混淆矩阵

```
                实际有幻觉    实际无幻觉
检测到幻觉        TP (真阳性)   FP (假阳性)
未检测到幻觉      FN (假阴性)   TN (真阴性)

假阳性率 = FP / (FP + TN)
召回率 = TP / (TP + FN)
```

**当前状态**（Week 5 实现完成）：
- 基础检测功能已完成
- 假阳性率和召回率测试计划在 Week 6 进行

## 使用场景

### 1. 学术写作

**风险点**：
- 编造论文引用
- 错误的统计数字
- 过时的研究结论

**推荐工作流**：
1. 运行同一问题 5 次，检查自洽性
2. 重点核实所有标记的引用和数字
3. 对低置信度段落，人工查阅原始文献

---

### 2. 金融分析

**风险点**：
- 编造财务数据
- 错误的市场趋势
- 虚假的公司信息

**推荐工作流**：
1. 检查所有数字的熵值
2. 对低熵但可疑的数字，交叉验证多个数据源
3. 对高不确定性的预测，标注"模型不确定"

---

### 3. 医疗咨询

**风险点**：
- 编造药物剂量
- 错误的诊断建议
- 过时的治疗方案

**推荐工作流**：
1. **禁止直接使用**：任何医疗建议必须人工审核
2. 使用本工具标记高风险内容
3. 所有建议必须有可靠来源支撑

**重要声明**：
本工具不能替代专业医疗判断。任何医疗决策必须由持证医生做出。

---

### 4. 法律审查

**风险点**：
- 编造法条
- 错误的判例引用
- 自相矛盾的陈述

**推荐工作流**：
1. 运行多次，检查陈述一致性
2. 核实所有法条和判例引用
3. 对低置信度段落，重新生成或人工改写

## 最佳实践

### 1. 何时运行多次？

**推荐**：
- 关键决策场景（金融、医疗、法律）：至少 5 次
- 学术写作：3-5 次
- 创意写作、日常对话：1 次即可

### 2. 如何解读多个异常？

**规则**：
- 1-2 个异常：正常波动，重点关注即可
- 3-5 个异常：中等风险，建议部分改写
- 5+ 个异常：高风险，建议重新生成或大幅改写

### 3. 低熵但错误的内容怎么办？

**现象**：
模型熵值很低（< 1.0），看起来很确信，但实际是错的。

**应对**：
- 事实性风险标记会捕获这类情况（低熵数字、引用）
- 关键数字和引用，无论熵值高低，都建议人工核实

### 4. 如何提高生成质量？

**Prompt 优化**：
- 添加"请逐步推理"、"不确定时说'不知道'"
- 要求提供信息来源
- 使用 Few-shot 示例

**参数调整**：
- 降低 temperature（0.3-0.7）减少随机性
- 提高 top_p（0.9-0.95）保留主流候选

## 常见问题

### Q1: 置信度评分 100 分就代表完全正确吗？

**A**: 不是。100 分只代表"模型非常确信，且多个维度都没有检测到异常"，但不保证内容真实。关键事实仍需人工核实。

### Q2: 我应该相信熵值还是置信度评分？

**A**: 两者结合看。熵值是单个 token 的不确定性，置信度评分是整体评估。高熵 token 需要关注，但低熵不保证正确。

### Q3: 为什么同样的内容，多次分析结果不同？

**A**: 如果是单次运行分析，结果应该完全相同。如果包含多次运行的自洽性分析，每次运行的输出可能不同（因为采样随机性），所以自洽性评分会变化。

### Q4: 我可以在商业项目中使用这个工具吗？

**A**: 可以。本项目采用 MIT 许可协议，允许商业使用。但请遵守学术引用规范。

### Q5: 这个工具支持哪些语言？

**A**: 当前主要测试中文和英文。其他语言的阈值可能需要调整，欢迎贡献经验数据。

### Q6: 我发现了一个误报/漏报，如何反馈？

**A**: 请提交 GitHub Issue，附上：
- 完整的 prompt 和生成内容
- 模型和参数
- 您认为正确的判断
- （可选）导出的 .aitrace 文件
